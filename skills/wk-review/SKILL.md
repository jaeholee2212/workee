# 검토
1. [필요한 기록 규약](../wk-work/references/registry.md#필요한-규약-선택)과 검토할 대상 버전을 읽는다.
2. 검토 파일이 배정되지 않았으면 [산출물 저장 규칙](../wk-work/references/registry.md#산출물-저장)에 따라 작업 기록 담당자에게 경로 배정을 요청한다.
3. 대상에 맞는 아래 검토를 수행한다.
4. 진행 가능, 보완 필요, 중단 제안 중 하나를 근거와 함께 적는다.
5. 판단을 바꿀 수 있는 미정에는 다음 조사나 필요한 사용자 판단을 연결한다.
6. 지정된 검토 파일만 쓴다.
7. 검토 결과를 작업 기록 담당자에게 반환한다.

검토 담당자는 작업의 상태를 바꾸지 않는다.
검토자에게 전달된 독립적인 관점과 반박할 대상을 확인한다.
검토자 간 동의는 관찰·자료·실험의 근거를 대신하지 않는다.
별도 검토자의 통과 판정은 인간과의 공동 검토나 실행 위임을 대신하지 않는다.

## 문제 검토
- 문제 진술을 원래 관찰과 사용자 목표에 대조한다.
- 특정 해결책이나 미확인 가정이 문제·제약에 섞였는지 확인한다.
- 현재 설명으로 설명되지 않는 사용 상황과 반례를 찾는다.
- 문제를 다르게 설명하면 범위나 완료 조건이 달라지는지 확인한다.

## 설계·계획 검토
- 구현 전에도 문제·비교·결정·계약·계획을 검토 대상으로 삼는다.
- 유력한 다른 대안이 더 나은 조건을 확인한다.
- 같은 사용 사례와 실패 상황에서 후보 간 차이를 근거와 대조한다.
- 선택을 뒤집을 미정은 [결정 준비](../wk-decide/references/readiness.md#결정-준비)에 따라 평가한다.
- 계획의 각 결과와 검증 방법을 원래 완료 조건에 연결한다.
- 선행 가정이 틀렸을 때 영향받을 결정과 작업을 확인한다.
- 사용자의 피드백이 문제·설계에 반영됐는지 실제 [공동 검토 기록](../wk-work/references/work-model.md#공동-검토와-실행-위임)과 대조한다.
- 아직 함께 검토하지 않은 제안과 합의된 선택을 구분한다.
- 공동 탐구를 거친 설계는 [탐구 완료](../wk-work/policies/collaboration.md#탐구-완료)의 근거와 남은 불확실성의 처리를 대조한다.
- 보류·수용·위임한 논점이 실행 준비 완료로 잘못 해석됐는지 확인한다.
- 인간과 논의할 반례·미해결 차이는 [탐구 논점](../wk-work/references/work-model.md#탐구-논점)의 영향·선행 관계와 함께 반환한다.

## 구현 결과 검토
- 문제와 선택 이유를 읽은 뒤 diff를 본다.
- 커밋 후보를 전달받았으면 [후보](../wk-work/references/work-model.md#커밋-후보)의 부모 `P`·트리 `T`와 그 diff를 검토 대상으로 삼는다.
- 후보 검토의 추가 조사는 해당 후보와 일치하는 검증 위치에서 수행한다.
- 후보 이외의 구현 결과이면 전달받은 워크트리·브랜치·실제 변경 버전을 검토 대상으로 삼는다.
- 계약, 범위, 호환성, 검증 근거와 실제 변경을 대조한다.
- 판단과 구체적 근거를 별도 검토 파일에 남긴다.

## 의견 처리
- 의견마다 수정, 기각, 추가 확인 중 하나를 기록한다.
- 기각에는 근거를 붙인다. 동의만으로 수정하지 않는다.
- 검토 안에서 확인할 수 있는 근거는 직접 조사한다.
- 다른 작업이 필요한 의견은 필요한 입력과 영향을 반환한다.
- 수정본이 검토 대상으로 전달되면 영향받은 근거를 다시 확인한다.

## 결과

- 요청된 검토 범위의 의견마다 근거와 처리 필요 사항이 있으면 검토를 마친다.
- 검토 작업의 완료와 검토 대상의 통과를 구분한다.
- 대상 버전·판정·반례·남은 미정을 [스킬 실행 결과](../wk-work/references/work-model.md#스킬-실행-결과)로 반환한다.
