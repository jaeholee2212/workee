# 통합

1. [장부 규약](../wk-work/references/registry.md)과 유효한 전체 검증·필요한 검토 결과를 읽는다.
2. 소유 마스터의 작업 브랜치·워크트리와 승인된 통합 대상을 확인한다.
3. 반영할 커밋의 실제 내용과 전체 검증 대상이 일치하는지 확인한다.
4. 필요한 장기 계약이 해당 커밋의 제품 문서에 반영됐는지 확인한다.
5. 장부의 조사 근거와 공식 제품 문서의 원본 연결을 확인한다.
6. 개발자가 승인한 방법과 범위로 대상 브랜치에 반영한다.
7. 실제 반영 버전과 남은 검증을 기록한다.

통합 대상이나 방법이 미정이면 필요한 입력으로 반환한다.
공유 공간의 하위 작업 완료를 위해 별도 브랜치 병합을 만들지 않는다.
반영할 결과에 필요한 미커밋 변경이 남으면 누락된 결과와 준비 조건을 반환한다.
제품 문서의 보완이 필요하면 해당 내용과 영향을 반환한다.
통합 준비 중 새로운 구현이나 문서 변경을 검증 없이 끼워 넣지 않는다.
로컬 커밋의 존재만으로 전체 목표 검증을 통과했다고 판단하지 않는다.
대상 작업공간에 다른 변경이 있으면 보존 방법을 확인한 뒤 진행한다.
통합 승인을 푸시·브랜치 삭제·워크트리 제거의 승인으로 확대하지 않는다.
필요한 사용자 판단은 [자율 진행과 사용자 판단](../wk-work/policies/progression.md#자율-진행과-사용자-판단)을 따른다.

## 결과

- 승인된 변경이 지정된 대상에 실제 반영됐는지 확인한다.
- 반영 버전·범위와 남은 검증을 [스킬 실행 결과](../wk-work/references/work-model.md#스킬-실행-결과)로 반환한다.
- 통합 결과와 작업 전체의 완료 판정을 구분한다.
