# 검증된 변경 커밋

이 스킬은 커밋 후보 준비와 검증된 후보의 로컬 커밋 생성을 수행한다.
변경 단위의 선택·검증 배정·다음 작업 선택은 `wk-work`가 담당한다.

## 입력 확인

1. [장부 규약](../wk-work/references/registry.md)과 현재 작업의 구현 공간을 읽는다.
2. 요청된 결과가 후보 준비인지 커밋 생성인지 확인한다.
3. [커밋 후보](../wk-work/references/work-model.md#커밋-후보)의 범위·식별자·근거를 확인한다.
4. 소유 작업에 기록된 브랜치·워크트리와 실제 실행 위치를 대조한다.
5. 현재 HEAD·index·미커밋 변경·진행 중 Git 작업과 Git 쓰기 담당자를 확인한다.
6. 로컬 커밋의 권한은 [진행 정책](../wk-work/policies/progression.md#자율-진행과-사용자-판단)으로 확인한다.

다른 작성자가 Git 상태를 변경 중이면 필요한 쓰기 종료 조건을 반환한다.
병합·rebase·cherry-pick 등 진행 중인 Git 작업이나 미해결 충돌이 있으면 기존 상태를 보존하고 해소 조건을 반환한다.
후보에 영향을 주는 파일의 쓰기가 계속되면 고정된 검증 위치가 필요한 이유를 반환한다.
기존 사용자 변경과 후보 밖의 staged 변경은 보존한다.

## 커밋 후보 준비

1. 전달받은 변경 이유와 포함·제외 범위를 실제 diff에 대조한다.
2. 해당 변경에 필요한 구현·테스트·문서가 후보에 포함됐는지 확인한다.
3. [후보 구성](references/git-candidate.md#후보-구성)으로 부모 커밋 `P`와 전체 tree `T`를 고정한다.
4. [검증 위치](references/git-candidate.md#검증-위치)에 따라 후보만의 상태를 확인할 위치를 준비한다.
5. `P`·`T`·포함·제외 범위·검증 위치와 필요한 검사를 반환한다.

후보 준비만으로 커밋을 생성하지 않는다.
다른 미커밋 변경과 분리할 수 없으면 필요한 변경의 묶음과 이유를 반환한다.
실제 검사·검토의 결과는 `wk-work`가 배정한 실행에서 받는다.

## 검증된 후보 커밋 생성

1. 후보의 `P`·`T`에 연결된 필수 검사와 필요한 검토의 유효한 통과 근거를 확인한다.
2. 현재 HEAD가 `P`인지 확인한다.
3. [커밋 생성](references/git-candidate.md#커밋-생성)에 따라 실제 커밋할 내용이 `T`인지 확인한다.
4. 저장소의 기존 커밋 메시지 규칙으로 변경 이유를 적는다.
5. 기존 훅을 적용해 로컬 커밋을 생성한다.
6. 생성된 커밋 SHA·부모·tree와 남은 변경을 확인한다.
7. 실제 부모가 `P`이고 실제 tree가 `T`인지 판정한다.

변경의 검증 범위는 해당 결과의 계약과 영향에 맞춘다.
매 커밋마다 전체 목표 검증을 요구하지 않는다.
부모 `P`·트리 `T`와 검사 조건이 같은 후보의 유효한 근거는 재사용할 수 있다.

## 불일치와 실패

- HEAD나 후보 내용이 달라졌으면 새 후보와 필요한 검증을 반환한다.
- 훅이 실패했으면 실제 HEAD와 남은 변경을 확인한다.
- 훅이나 동시 쓰기가 커밋 내용을 바꿨으면 생성된 SHA와 불일치를 반환한다.
- 검증되지 않은 커밋이 생성됐으면 그 커밋을 검증된 결과로 사용하지 않는다.
- 실패나 불일치를 숨기려고 훅을 건너뛰거나 커밋을 자동으로 amend·reset하지 않는다.
- 재시도 전에는 이전 실행에서 커밋이 이미 생성됐는지 확인한다.

## 완료와 결과

- 후보 준비는 `P`·`T`와 검증 위치의 내용 일치 근거가 있으면 완료다.
- 커밋 생성은 필수 근거가 유효하고 실제 부모·tree가 후보와 일치할 때만 완료다.
- 후보 식별자·검증 근거·생성 SHA·동일성 판정·남은 변경을 [스킬 실행 결과](../wk-work/references/work-model.md#스킬-실행-결과)로 반환한다.
- 로컬 커밋은 전체 작업 완료·대상 브랜치 통합·푸시를 뜻하지 않는다.
