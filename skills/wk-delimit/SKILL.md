# 문제 한정
1. [장부 규약](../wk-work/references/registry.md)을 읽는다.
2. 관찰 근거를 읽는다.
3. 기존 진단이 있으면 그 결과를 읽는다.
4. 충족되지 않은 사용자 목표와 근거가 있는 장애물을 연결한다.
5. 요청된 해결책은 문제 진술과 구분한다.
6. 문제의 핵심을 한 문장으로 `work.md`에 기록한다.

## 범위
- 해결 후 사용자가 달성할 결과와 관련 사용 상황을 적는다.
- 그 결과를 판정할 관찰 가능한 조건을 적는다.
- 확인된 제약, 사용자가 선택한 제약, 아직 검증하지 않은 가정을 구분한다.
- 이번 작업의 제외 범위와 그 이유를 적는다.

## 재정의
- 문제 설명과 맞지 않는 관찰이 있으면 해당 부분을 [탐색 반복](../wk-work/references/exploration.md#탐색-반복)으로 조사한다.
- 새 근거로 문제 설명이 바뀌면 영향받는 대안과 완료 조건을 표시한다.
- 목표나 범위의 변경 판단은 [자율 진행과 사용자 판단](../wk-work/SKILL.md#자율-진행과-사용자-판단)을 따른다.

## 작업 분리
- 같은 목표의 기록이 있으면 새 작업 대신 연결한다.
- 독립된 목표나 별도 담당자가 필요하면 분리한다.
- 전체 목표에 기여하는 하위 결과면 [공통 작업 모델](../wk-work/references/work-model.md)에 따라 상위 작업을 연결한다.
- 별개의 목표나 범위 분리의 출처는 관련·원작업 링크로 남긴다.
- 구체적인 하위 결과와 검증 방법은 [wk-plan](../wk-plan/SKILL.md)에서 정한다.
