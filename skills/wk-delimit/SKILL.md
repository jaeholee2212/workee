# 문제 한정
1. [필요한 기록 규약](../wk-work/references/registry.md#필요한-규약-선택)을 읽는다.
2. 관찰 근거를 읽는다.
3. 기존 진단이 있으면 그 결과를 읽는다.
4. 충족되지 않은 사용자 목표와 근거가 있는 장애물을 연결한다.
5. 요청된 해결책은 문제 진술과 구분한다.
6. 문제의 핵심을 한 문장으로 정리한다.

## 범위
- 해결 후 사용자가 달성할 결과와 관련 사용 상황을 적는다.
- 그 결과를 판정할 관찰 가능한 조건을 적는다.
- 확인된 제약, 사용자가 선택한 제약, 아직 검증하지 않은 가정을 구분한다.
- 이번 작업의 제외 범위와 그 이유를 적는다.

## 재정의
- 문제 설명과 맞지 않는 관찰이 있으면 원자료와 사용 상황을 대조한다.
- 주어진 근거로 설명을 고칠 수 있으면 문제 진술을 갱신한다.
- 원인 조사나 새로운 관찰이 필요하면 확인할 질문과 영향을 남긴다.
- 새 근거로 문제 설명이 바뀌면 영향받는 대안과 완료 조건을 표시한다.
- 목표나 범위의 변경 판단은 [자율 진행과 사용자 판단](../wk-work/policies/progression.md#자율-진행과-사용자-판단)을 따른다.

## 작업 분리
- 같은 목표의 기록이 있으면 연결할 기존 작업을 결과에 포함한다.
- 독립된 목표가 발견되면 분리할 문제와 그 이유를 적는다.
- 전체 목표에 기여하는 결과와 별개 목표를 구분한다.
- 관계 후보는 [공통 작업 모델](../wk-work/references/work-model.md#포함-관계)에 맞춰 제안한다.

## 완료와 결과
- 문제·목표·범위가 관찰 근거와 연결되고 완료 조건으로 결과를 판정할 수 있는지 확인한다.
- 해결책을 전제한 제약이나 설명되지 않은 관찰이 남으면 보완할 부분을 반환한다.
- [스킬 실행 결과](../wk-work/references/work-model.md#스킬-실행-결과)에 따라 문제 진술·범위·관계 후보를 반환한다.
