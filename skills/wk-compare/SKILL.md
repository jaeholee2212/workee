# 대안 비교
1. [필요한 기록 규약](../wk-work/references/registry.md#필요한-규약-선택)과 현재 문제를 읽는다.
2. 이번 비교가 결정할 방향이나 구현 방식을 명시한다.
3. 사용자 결과와 제약에서 선택을 가르는 설계 축을 찾는다.
4. 현상 유지안을 비교의 기준점으로 둔다.
5. 가정이나 책임 배치가 다른 접근을 만든다.
6. 각 접근의 동작과 성립 조건을 짧게 설명한다.

## 설계 축과 후보

- 설계 축은 계산 시점, 상태의 위치, 갱신 책임, 해결할 경계처럼 접근의 구조를 바꾸는 차이다.
- 같은 문제를 해결한 기존 사례가 있으면 그 접근과 적용 조건을 조사한다.
- 각 유력 후보가 가장 유리한 조건을 적는다.
- 각 유력 후보를 탈락시킬 관찰이나 반례를 적는다.
- 후보가 하나만 남으면 다른 접근을 제외한 근거를 적는다.

## 비교표
- 사용자 결과와 제약에 연결되는 기준만 행으로 둔다.
- 유력 후보에는 같은 사용 사례와 중요한 실패 상황을 적용한다.
- 셀에는 각 기준을 다루는 방식과 근거를 적는다.
- 측정값은 조건과 출처를 함께 적는다.
- 숫자 점수로 차이와 판단 근거를 대신하지 않는다.
- 비용과 약점도 해당 후보의 셀에 적는다.
- 모르는 셀에는 ?와 확인할 질문을 적는다.

## 비교의 갱신

- 선택을 바꿀 가능성과 잘못 판단할 비용이 큰 미정을 고른다.
- 조사 전에 가능한 결과가 후보의 평가에 미칠 영향을 적는다.
- 일차 자료와 직접 관찰에서 해당 차이를 확인한다.
- 필요한 가역적 실험은 [자율 진행과 사용자 판단](../wk-work/policies/progression.md#자율-진행과-사용자-판단)의 범위에서 수행한다.
- 확인한 근거의 위치와 버전을 적는다.
- 추론은 확인된 사실과 구분한다.
- 새 근거에 따라 비교 기준과 후보를 갱신한다.
- 사용자 답변이나 반례가 들어오면 기존 권고안에도 같은 기준을 적용한다.
- 비교에서 드러난 장단점으로 더 나은 접근을 만들 수 있으면 후보를 수정하거나 추가한다.
- 후보를 결합하면 결합으로 생긴 비용과 상호작용도 비교한다.
- 비교 범위 안에서 중요한 미정을 더 확인할 수 있으면 다음 조사를 이어 간다.
- 정보가 늘지 않으면 자료·가정·사용 상황을 바꿔 차이를 확인한다.
- 문제의 전제가 깨지거나 다른 작업의 산출물이 필요하면 필요한 입력과 영향을 반환한다.

작은 가역적 선택은 필요한 차이만 확인한다.
영향이 크거나 되돌리기 어려운 선택은 가장 강한 반대안과 실패 상황을 비교한다.
후보 수나 반복 횟수를 채우기 위해 조사를 늘리지 않는다.

## 완료와 결과

- 유력 후보와 제외한 후보의 차이를 근거로 설명한다.
- 중요한 비교 기준이 같은 사용 사례의 근거로 설명되는지 확인한다.
- 확인하지 못한 차이는 선택에 미치는 영향과 필요한 자료를 적는다.
- 권고안을 바꾸거나 유지한 이유와 새로 열린 논점의 선행 관계를 [탐구 논점](../wk-work/references/work-model.md#탐구-논점)에 맞춰 반환한다.
- [스킬 실행 결과](../wk-work/references/work-model.md#스킬-실행-결과)에 따라 비교 결과와 남은 미정을 반환한다.
