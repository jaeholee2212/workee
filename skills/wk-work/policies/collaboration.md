# 공동 탐구

`wk-work`가 논의·계획에서 사용자와 문제·대안·설계를 함께 발전시킬 때 읽는다.
기존 합의의 재사용과 실행 권한은 [진행 정책](progression.md#자율-진행과-사용자-판단)을 따른다.

## 대화와 탐색의 반복

1. 첫 조사로 확인한 사실과 현재 해석을 구분한다.
2. 설계를 확정하기 전에 사용자의 경험이나 반례와 대조할 핵심 논점을 제시한다.
3. 사용자 응답으로 확인된 내용과 달라진 해석을 정리한다.
4. 남은 질문을 판별할 조사·비교·실험을 하위 스킬에 배정한다.
5. 중요한 새 근거와 선택의 차이를 다음 대화에 가져온다.
6. 함께 검토한 결과를 [공동 검토와 실행 위임](../references/work-model.md#공동-검토와-실행-위임)에 기록한다.

초기 해석이 바뀔 수 있을 때 첫 대화를 연다.
모든 분석과 계획을 완성한 뒤 마지막 승인 질문만 남기는 방식으로 이 반복을 대체하지 않는다.
사용자 답변이 없어도 판별할 사실은 조사한다.
답변에 의존하는 선택은 잠정안으로 유지한다.

## 함께 검토할 내용

| 대상 | 대화에 가져올 내용 |
| --- | --- |
| 문제 | 관찰한 현상·사용자의 실제 경험·가능한 다른 설명·해결할 문제와 제외 범위 |
| 대안 | 같은 사용 사례에서의 차이·판단 기준·강한 반대안·권고안이 불리해지는 조건 |
| 설계 | 주요 사용 흐름·실패 상황·책임과 데이터 경계·사용자 행동과 운영 부담의 변화 |
| 실행 계획 | 합의한 설계를 구현할 단위·선행 조건·검증 방법·남은 위험·위임할 실행 범위 |

LLM의 권고와 사용자가 확인한 내용을 구분한다.
대화에서 새로운 기준이나 대안이 나오면 이전 비교와 설계를 갱신한다.
답변을 반영해 달라진 점과 유지한 판단의 이유를 사용자에게 설명한다.
기술적 선택이어도 사용자 경험·운영 부담·되돌리기 비용을 바꾸면 공동 검토 대상으로 삼는다.

## 논점 제시

- 한 번에 함께 판단할 수 있는 핵심 논점부터 다룬다.
- 관찰·현재 해석·불확실성·질문의 이유를 짧게 연결한다.
- 선택이 필요하면 실제 차이와 권고 근거를 함께 제시한다.
- 비교가 어려우면 같은 사용 사례를 따라가는 예시·표·작은 도식으로 차이를 드러낸다.
- 사용자가 경험·반례·새 대안을 보탤 여지를 남긴다.
- 코드나 자료에서 찾을 사실은 직접 확인한다.
- 대화의 깊이는 중요한 불확실성과 선택의 영향에 맞춘다.

질문 수나 대화 횟수를 완료 기준으로 삼지 않는다.
기술 용어는 현재 판단에 필요한 뜻을 설명한다.
공동 검토의 진척은 새롭게 공유한 이해와 그로 인해 달라진 문제·기준·선택으로 확인한다.

## 전환과 재개

논의·계획의 전환에서는 근거의 충분성과 실제 대화에서 확인된 합의를 각각 확인한다.
계획 초안 작성과 사용자가 그 계획의 실행을 맡긴 상태를 구분한다.
실행 중 합의의 중요한 전제가 깨지면 새 근거와 영향을 해당 논의로 가져온다.
아직 유효한 합의와 그 범위 안의 독립적인 실행은 유지한다.
반환된 응답이 무엇을 확인한 것인지 불분명하면 필요한 범위만 질문한다.
