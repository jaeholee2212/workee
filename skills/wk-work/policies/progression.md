# 진행 정책

`wk-work`가 스킬 선택·재실행·단계 전환과 사용자 질문을 조율한다.
하위 스킬은 맡은 결과를 만들기 위한 내부 조사를 반복한다.
다른 스킬의 실행이나 전체 단계 전환이 필요하면 [스킬 실행 결과](../references/work-model.md#스킬-실행-결과)로 돌려준다.

## 자율 진행과 사용자 판단

- 현재 요청의 범위와 제한을 우선한다.
- 이미 확인된 사용자 선호와 승인 범위를 재사용한다.
- 요청한 결과에 필요한 조사·비교·반박·재정의는 계속 배정한다.
- 자료·코드·관찰로 확인할 사실은 해당 스킬이 조사하게 한다.
- 실제로 위임된 기술적 선택은 결정 스킬에 맡긴다.
- 논의·계획 중 필요한 가역적인 로컬 실험은 제품 변경과 분리해 수행할 수 있다.
- 사용자 데이터나 외부 시스템에 영향을 주는 실험은 해당 행동의 승인 범위를 확인한다.
- 논의·계획에서는 [공동 탐구](collaboration.md)로 문제·대안·설계를 사용자와 함께 검토한다.
- 여러 과정을 맡겼으면 아래 전환 조건을 충족하는 다음 과정까지 이어 간다.
- 논의·계획만 요청했으면 제품 구현은 그 범위에 포함하지 않는다.
- 합의한 계획의 실행 위임에는 해당 범위의 구현·검증과 작업 브랜치의 로컬 커밋을 포함한다.
- 사용자가 커밋을 제외하거나 시점을 제한했으면 그 제한을 우선한다.
- 기존 사용자 변경이나 다른 작업의 변경은 포함 범위가 확인되지 않으면 커밋 후보에서 제외한다.
- 로컬 커밋을 대상 브랜치 통합·푸시·이력 재작성의 승인으로 확대하지 않는다.
- 위임이 가능한 환경에서는 요청 범위 안의 조사·구현·검증·검토를 서브에이전트에 맡길 수 있다.
- 구현의 위임 기준은 [실행자 선택](../workflows/implement.md#실행자-선택)을 따른다.

### 합의와 실행 위임

근거의 충분성, 사용자와의 합의, 실행 위임을 각각 확인한다.
그 근거는 [공동 검토와 실행 위임](../references/work-model.md#공동-검토와-실행-위임)에 기록한다.

- 새 목표의 포괄적인 “만들어줘”나 “개선해줘”는 문제와 설계를 함께 검토할 출발점으로 사용한다.
- 논의한 문제·범위·방향에 대한 사용자 의견이 반영되면 그 근거로 계획을 구체화한다.
- 계획의 주요 동작·대안·비용·검증 방법을 함께 검토한 뒤 해당 계획의 실행을 맡긴 근거를 확인한다.
- 실행 위임이 확인되면 그 범위에서 구현·검증·커밋을 추가 진행 지시 없이 이어 간다.
- 사용자의 짧은 동의는 직전 대화의 대상과 범위에 연결한다.
- 실행 요청에 대한 동의가 명확하면 특정 승인 문구나 새 서식을 요구하지 않는다.
- 방향이나 설명에 대한 동의만으로 제품 구현의 위임을 추정하지 않는다.
- 설명 전달·LLM의 계획 완성·사용자의 무응답을 사용자 합의의 근거로 사용하지 않는다.

기존 합의와 실행 위임이 현재 계획에 유효하면 그 근거를 재사용한다.
사용자가 설계 선택과 실행까지 명시적으로 맡겼으면 그 위임 범위를 기록하고 진행한다.
사용자가 대상·수정 내용을 구체적으로 지시한 작은 변경은 그 지시를 해당 범위의 설계·실행 위임으로 사용할 수 있다.
단순 사실 확인이나 조사 보고서 요청은 요청한 답과 근거를 반환한다.
설계·계획 초안이나 대안 보고서만 요청했으면 미확인 가정과 미합의 선택을 명시해 그 결과를 반환한다.
초안의 완료를 확정 계획이나 제품 구현의 실행 위임으로 확대하지 않는다.

### 합의 변경과 재검토

- 새 근거가 알려진 요구와 충돌하거나 핵심 전제·사용자 동작·범위·주요 비용을 바꾸면 영향받는 부분을 [공동 검토](collaboration.md)한다.
- 기존 위임을 벗어나는 중요한 새 선택도 공동 검토 대상으로 삼는다.
- 재검토할 합의에 의존하는 구현·커밋은 대기시킨다.
- 아직 유효한 합의와 그 범위 안의 독립적인 실행·조사는 유지한다.
- 합의 안의 구현 세부나 검사 보완은 기존 실행 위임으로 처리한다.
- 바뀐 합의와 실행 위임을 기록한 뒤 영향받는 결과부터 재개한다.
- 사용자 응답이 확인한 대상이나 범위가 불분명하면 필요한 부분만 질문한다.

### 질문과 대기

논의·계획의 질문은 [공동 탐구](collaboration.md)의 이해와 대안 검토를 위해 사용한다.
실행을 위임받은 뒤에는 다음 판단이 필요하고 기존 근거로 정할 수 없을 때 사용자에게 묻는다.

- 사용자만 정할 수 있는 목표의 우선순위나 상충하는 요구
- 조사로 확정할 수 없는 작업 대상이나 기록 원본의 선택
- 기존 합의에 없는 중요한 비용·위험의 수용
- 요청 범위를 넓히거나 별도 권한이 필요한 행동

질문에는 필요한 판단·선택별 영향·권고안을 담는다.
답을 기다리는 동안 그 판단에 의존하는 행동만 대기시킨다.
독립적인 조사·검토는 계속 배정한다.
답이 필요한 부분은 잠정 상태로 유지한다.
독립적인 조사를 마쳐도 필요한 응답이 없으면 현재 근거와 논점을 반환하고 대화의 다음 차례를 기다린다.
같은 범위의 합의나 위임을 단계·스킬 전환만으로 다시 묻지 않는다.
기존 범위 안의 실행자 배정만으로 사용자에게 별도 허락을 묻지 않는다.
현재 허용된 범위의 로컬 커밋마다 허락을 다시 묻지 않는다.
확인할 수 없는 사실은 미확인으로 유지한다.

하위 스킬을 직접 요청받았으면 그 스킬의 범위 안에서 같은 정책을 적용한다.
`wk-work`가 배정한 하위 스킬은 필요한 사용자 판단을 반환한다.
직접 요청받은 하위 스킬은 이 기준에 해당하는 질문을 직접 한다.
직접 요청한 스킬의 결과를 반환한 뒤 다른 단계로 자동 확장하지 않는다.

## 결과에 따른 반복

1. 현재 단계의 완료 조건과 유효한 산출물을 대조한다.
2. 부족한 결과에 맞는 하위 스킬을 선택한다.
3. 요청할 결과·입력 근거·실행 범위·담당할 기록을 전달한다.
4. [스킬 실행 결과](../references/work-model.md#스킬-실행-결과)와 사용자 피드백을 받아 현재 이해에 통합한다.
5. 새 근거로 무효화된 결정·계약·계획에 의존하는 실행을 대기시킨다.
6. 단계별 조율 문서로 다음 스킬이나 복귀할 단계를 선택한다.
7. 요청한 결과의 완료 조건을 충족할 때까지 반복한다.

- 한 스킬의 완료는 전체 단계나 작업의 완료를 뜻하지 않는다.
- 반환된 미정 중 결론을 바꿀 가능성과 잘못 판단할 비용이 큰 것을 먼저 배정한다.
- 같은 질문이면 비용이 낮고 후보를 구분할 수 있는 조사부터 배정한다.
- 작은 가역적 선택에는 필요한 차이만 확인하도록 범위를 좁힌다.
- 중요한 선택에는 강한 반대안과 실패 상황을 확인하는 검토를 배정한다.
- 조사 방법·실험 설계·대안 생성 방법은 하위 스킬이 정한다.
- 기존 근거가 충분하면 스킬을 다시 실행하는 대신 유효한 결과를 재사용한다.
- 합의에 영향을 주는 발견은 [합의 변경과 재검토](#합의-변경과-재검토)를 적용한다.

진척은 반환된 `새 근거 → 판단에 미친 영향 → 남은 질문`으로 확인한다.
같은 설명이나 에이전트 간 동의만 반복되면 자료·가정·관찰 상황을 바꾼 조사를 요청한다.
실행 가능한 유의미한 조사가 남으면 다음 행동의 제안만으로 끝내지 않는다.

## 종료와 재개

| 조건 | 조율 행동 |
| --- | --- |
| 요청한 결과의 완료 조건이 충족됐다. | 승인된 다음 단계가 있으면 실행하고, 없으면 결과를 응답한다. |
| 공동 검토의 응답이나 계획 실행 위임이 필요하다. | 준비한 근거와 논점을 제시하고 독립적인 조사만 이어 간다. |
| 사용자만 할 수 있는 판단이 남았다. | 해당 판단을 묻고 독립적인 작업을 계속한다. |
| 근거에 접근할 수 없고 대체 조사도 없다. | 미확인 내용·영향·재개에 필요한 자료를 기록한다. |
| 가능한 유의미한 조사를 마쳐도 중요한 차이를 판별할 수 없다. | 확인한 범위·판별할 수 없는 이유·남은 미정·재개할 조건을 기록한다. |
| 사용자가 정한 시간·비용 한도나 실제 실행 한도에 도달했다. | 가능한 판단과 유보할 판단, 가장 가치 있는 다음 조사를 기록한다. |

접근 제한·조사 소진·한도 도달을 준비 완료로 처리하지 않는다.
조건부 초안과 실행 가능한 결과를 구분한다.
사용자 답이나 새 근거가 오면 영향받은 결과부터 다시 배정한다.
사용자가 중단을 요청하면 현재 결과를 보존하고 중단한다.
