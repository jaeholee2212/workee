# 작업 조율

사용자는 목표와 원하는 진행 범위를 말한다.
이 스킬은 네 단계에서 필요한 하위 스킬을 선택하고 결과를 연결한다.
반복·단계 전환·사용자 질문·전체 완료 판정은 이 스킬이 책임진다.
논의·계획의 공동 검토와 합의한 계획의 실행 위임도 이 스킬이 확인한다.
서브에이전트의 위임·진행 추적·결과 회수와 합류 후 전체 검증도 이 스킬이 조율한다.
의미 있는 변경 단위의 선택·후보 검증·로컬 커밋과 다음 구현의 연결도 이 스킬이 책임진다.
실제 조사·설계·구현·검증 방법과 자기 결과의 완료 기준은 하위 스킬이 책임진다.

## 공통 규약

현재 행동에 필요한 절만 읽고, 이미 읽은 유효한 규약은 재사용한다.

| 읽을 때 | 규약 |
| --- | --- |
| 시작·재개 시 요청 범위와 권한을 판단한다. | [자율 진행과 사용자 판단](policies/progression.md#자율-진행과-사용자-판단) |
| 새 목표나 주요 설계를 논의·계획하거나 기존 합의의 변경을 다룬다. | [공동 탐구](policies/collaboration.md) |
| 설정·작업을 확인하거나 기록을 다룬다. | [필요한 기록 규약](references/registry.md#필요한-규약-선택) |
| 하위 스킬의 결과로 다음 행동을 정한다. | [스킬 실행 결과](references/work-model.md#스킬-실행-결과)와 [결과에 따른 반복](policies/progression.md#결과에-따른-반복) |
| 종료·대기·재개 여부를 정한다. | [종료와 재개](policies/progression.md#종료와-재개) |

## 시작·재개

1. 전달받은 자료에서 목표와 요청한 진행 범위를 확인한다.
2. [자율 진행과 사용자 판단](policies/progression.md#자율-진행과-사용자-판단)으로 기존 합의·실행 위임과 제한을 확인한다.
3. [필요한 기록 규약](references/registry.md#필요한-규약-선택)으로 설정 원본과 작업 기록을 확인한다.
4. 새 설정이나 장부가 필요하면 [wk-setup-workspace](../wk-setup-workspace/SKILL.md)에 초기화를 맡긴다.
5. 대상 작업을 찾거나 등록한다.
6. 상위 목표와 관련 하위 작업의 산출물·현재 이해를 확인한다.
7. 구현 작업공간이 기록돼 있으면 [wk-worktree](../wk-worktree/SKILL.md)에 재사용 확인을 맡긴다.
8. 유효한 근거·공동 검토·실행 위임과 현재 결과의 차이로 진행할 단계를 선택한다.

상태 확인이나 다음 행동 제안만 요청받으면 그 결과를 응답한다.
작업을 이어 달라는 요청이면 기존 목표와 승인 범위 안에서 다음 행동을 실행한다.
탐구의 시작·재개·작은 수정의 경계는 [적용 범위](policies/collaboration.md#적용-범위)로 판단한다.
기존 합의의 재사용·직접 실행·초안이나 조사 결과만 반환하는 조건은 [진행 정책](policies/progression.md#자율-진행과-사용자-판단)을 따른다.

## 단계별 조합

현재 단계의 조율 문서만 읽는다.
[결과에 따른 반복](policies/progression.md#결과에-따른-반복)으로 하위 스킬의 결과를 다음 실행에 연결한다.

| 단계 | 선택할 상황 | 조율 절차 |
| --- | --- | --- |
| 논의 | 문제·범위·방향에 중요한 미정이나 함께 검토할 내용이 있다. | [논의](workflows/discuss.md) |
| 계획 | 검토한 방향의 설계·계약·실행 계획을 구체화하거나 함께 검토해야 한다. | [계획](workflows/plan.md) |
| 구현 | 유효한 계약·계획과 해당 범위의 실행 위임이 확인됐다. | [구현](workflows/implement.md) |
| 검증 | 결과를 요청된 완료 조건과 대조해야 한다. 변경 단위와 전체 목표의 검증 범위를 구분한다. | [검증](workflows/verify.md) |

단계 문서는 필요한 스킬·입력·기대 결과·전환 조건을 정의한다.
하위 스킬의 작업 방법은 해당 스킬의 문서를 읽어 수행한다.

## 공통 조율

- 구현의 실행자 선택과 위임은 [구현 조율](workflows/implement.md#실행자-선택)을 따른다.
- 여러 작성자나 공유 자원이 있으면 [wk-coordinate](../wk-coordinate/SKILL.md)에 배정·충돌 조정을 맡긴다.
- 중요한 결정에 별도 검토가 필요하면 작성자와 다른 관점으로 [wk-review](../wk-review/SKILL.md)를 실행한다.
- 작업을 중단하거나 담당자를 넘기면 현재 상태·중단 사유·다음 행동을 정한다.
- 이 결과를 [wk-handoff](../wk-handoff/SKILL.md)에 전달해 보존·인계를 맡긴다.
- 스킬이 없으면 해당 행동의 누락을 기록하고 다른 가능한 행동을 선택한다.

## 기록과 응답

1. 반환된 근거로 현재 이해·유효한 산출물·남은 미정을 갱신한다.
2. 작업 기록 담당자가 [완료 판정](references/work-model.md#완료-판정)과 [기록 갱신](references/registry.md#기록-갱신)을 적용한다.
3. 작업 ID·현재 단계와 상태·결과와 근거·다음 행동이나 필요한 선택을 응답한다.

- 기록 갱신만 요청받으면 시작 질문이나 완료한 절차를 반복하지 않는다.
- 중요한 용어의 뜻이 갈리면 기존 정의를 확인한다.
- 확인된 용어 정의는 `wk-factory.yaml`의 `glossary.path` 파일에 저장한다.
- 구현 작업공간이 있으면 소유 작업·브랜치·워크트리 경로를 함께 알린다.
- 하위 작업을 다뤘으면 해당 작업과 마스터 작업의 완료 여부·남은 전체 목표를 함께 알린다.
