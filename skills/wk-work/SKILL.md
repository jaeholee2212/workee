# 작업 진행

사용자는 목표와 원하는 진행 범위를 말한다.
이 스킬은 필요한 빌딩 블록을 선택한다.
승인된 범위에서 결정에 필요한 근거가 쌓일 때까지 결과를 통합하고 다음 탐색을 이어 간다.

## 공통 규약

| 문서 | 책임 |
| --- | --- |
| [장부 규약](references/registry.md) | 설정·작업 식별·문서·색인·이력 |
| [공통 작업 모델](references/work-model.md) | 용어·기록 항목·단계·상태·관계·검증 근거·완료 판정 |

## 시작·재개

1. 전달받은 자료에서 목표와 요청한 진행 범위를 확인한다.
2. 장부 규약에 따라 대상 작업을 찾거나 등록한다.
3. 상위 작업이 있으면 전체 목표와 관련 완료 조건을 읽는다.
4. 하위 작업이 있으면 현재 요청에 필요한 작업과 산출물의 실제 상태를 확인한다.
5. 구현 작업공간이 기록돼 있으면 [wk-worktree](../wk-worktree/SKILL.md)의 재사용 절차를 수행한다.
6. 확인한 산출물 위치에서 기존 근거와 현재 결과의 차이를 확인한다.
7. 지금 필요한 진행 모드를 선택한다.

상태 확인이나 다음 행동 제안만 요청받으면 그 결과를 응답한다.
작업을 이어 달라는 요청이면 기존 목표와 승인 범위 안에서 다음 행동을 실행한다.

## 진행 모드

현재 모드의 문서만 읽는다.
모드 문서는 `시작 조건 → 진행 → 산출물 → 전환·중단` 순서로 읽는다.
유효한 기존 산출물은 재사용한다.
부족하거나 무효한 산출물에 필요한 빌딩 블록만 읽는다.
선택한 빌딩 블록의 절차를 수행한다.
빌딩 블록이 반환한 근거와 미정으로 다음 행동을 선택한다.
필요한 스킬이 없으면 누락을 알리고 그 절차를 보류한다.

| 모드 | 선택할 상황 | 절차 |
| --- | --- | --- |
| 논의 | 문제·범위·방향에 중요한 미정이 있다. | [논의](references/discuss.md) |
| 계획 | 방향을 구체적인 설계와 실행·검증 가능한 작업으로 바꿔야 한다. | [계획](references/plan.md) |
| 구현 | 승인된 계약과 변경 범위가 있고 실제 변경이 필요하다. | [구현](references/implement.md) |
| 검증 | 결과를 완료 조건과 대조하거나 전체 목표의 달성을 판정해야 한다. | [검증](references/verify.md) |

다음 모드는 각 문서의 전환 조건으로 선택한다.
논의·계획에서는 [탐색 규약](references/exploration.md)을 적용한다.

## 자율 진행과 사용자 판단

- 현재 요청이 제한한 범위를 과거의 포괄적 승인보다 우선한다.
- 요청한 결과를 만드는 데 필요한 조사·비교·반박·재정의는 스스로 이어 간다.
- 이미 확인된 사용자 선호와 승인 범위를 재사용한다.
- 자료·코드·관찰로 확인할 수 있는 사실은 직접 조사한다.
- 알려진 목표·제약으로 판단할 수 있는 기술적 선택은 근거와 함께 결정한다.
- 논의·계획 중 필요한 가역적인 로컬 실험은 제품 변경과 분리해 수행한다.
- 기존 사용자 데이터나 외부 시스템에 영향을 주는 실험은 해당 행동의 승인 범위를 확인한다.
- 여러 과정을 맡겼으면 준비 조건을 충족한 다음 과정까지 이어 간다.
- 논의·계획만 요청했으면 제품 구현은 그 범위에 포함하지 않는다.
- 위임이 가능한 환경에서는 요청 범위 안의 조사·검토를 분담할 수 있다.
- 병렬 작성이 필요하면 [wk-coordinate](../wk-coordinate/SKILL.md)로 작성 범위와 공유 자원을 조정한다.

다음 중 하나가 진행에 필요하고 기존 자료로 판단할 수 없을 때만 사용자에게 묻는다.

- 사용자만 정할 수 있는 목표의 우선순위나 상충하는 요구
- 기존 합의에 없는 중요한 비용·위험의 수용
- 요청 범위를 넓히거나 별도 권한이 필요한 행동

질문에는 필요한 판단, 선택별 영향과 권고안을 담는다.
답을 기다릴 때는 그 판단에 의존하는 행동만 대기시킨다.
독립적으로 진행할 수 있는 조사는 계속한다.
확인할 수 없는 사실을 사용자의 추측으로 확정하지 않는다.

## 범위와 중단

- 요청한 범위가 끝나면 결과와 근거를 응답한다.
- 단계나 스킬이 바뀌었다는 이유만으로 진행 여부를 다시 묻지 않는다.
- 탐색을 끝내거나 보류할 때는 [탐색 종료](references/exploration.md#탐색-종료)의 사유를 기록한다.
- 작업을 중단하거나 담당자를 넘기면 [wk-handoff](../wk-handoff/SKILL.md)를 사용한다.

## 기록과 응답

1. 작업 기록 담당자가 현재 근거로 [완료 판정](references/work-model.md#완료-판정)을 적용한다.
2. [기록 갱신](references/registry.md#기록-갱신)으로 결과를 반영한다.
3. 작업 ID·현재 단계와 상태·결과와 근거·다음 행동이나 필요한 선택을 응답한다.

- 기록 갱신만 요청받으면 시작 질문이나 완료한 절차를 반복하지 않는다.
- 중요한 용어의 뜻이 갈리면 기존 정의를 확인한다.
- 확인된 용어 정의는 `wk-factory.yaml`의 `glossary.path` 파일에 저장한다.
- 구현 작업공간이 있으면 소유 작업·브랜치·워크트리 경로를 함께 알린다.
- 하위 작업을 다뤘으면 해당 작업과 마스터 작업의 완료 여부·남은 전체 목표를 함께 알린다.
