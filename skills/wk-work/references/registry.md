# 장부 규약

작업을 찾고 읽고 갱신하는 방법을 정의한다.

## 필요한 규약 선택

현재 행동에 해당하는 절과 그 절에서 요구하는 참조만 읽는다.
이미 읽은 규약과 전달받은 설정 원본·작업·작성 범위가 유효하면 재사용한다.

| 현재 행동 | 읽을 규약 |
| --- | --- |
| 설정·장부 위치가 아직 확인되지 않았다. | [설정 확인](#설정-확인) |
| 작업을 찾거나 등록·재개한다. | [작업 식별](#작업-식별)과 [문서 관리](#문서-관리) |
| 맡은 결과를 반환한다. | [스킬 실행 결과](work-model.md#스킬-실행-결과) |
| 작업 기록을 갱신한다. | [문서 관리](#문서-관리)와 [기록 갱신](#기록-갱신) |
| 독립 산출물을 저장하거나 수정본을 만든다. | [산출물 저장](#산출물-저장) |
| 작업을 생성하거나 포함 관계를 바꾼다. | [색인 관리](#색인-관리) |
| 기존 형식의 기록을 이어서 다룬다. | [기존 기록과 호환](#기존-기록과-호환) |
| 권한이나 사용자 판단이 필요하다. | [자율 진행과 사용자 판단](../policies/progression.md#자율-진행과-사용자-판단) |

직접 요청받고 유효한 작업 입력이 없으면 설정 확인·작업 식별로 대상을 확인한다.
배정받은 입력·기록 범위가 불충분하면 필요한 확인이나 선택을 반환한다.

## 설정 확인

1. 전달받은 설정 원본 경로가 있으면 그 `wk-factory.yaml`을 우선 확인한다.
2. 원본 경로가 없으면 현재 프로젝트의 `wk-factory.yaml`을 찾는다.
3. Git 연결 워크트리이면 아래 절차로 설정 원본을 확정한다.
4. 원본 위치가 확정됐지만 설정이나 장부 가이드가 없으면 누락 항목과 확인한 원본 경로를 반환한다.
5. 설정 파일의 `project.id`, `registry.root`, `registry.guide`, `work.id_prefix`를 확인한다.
6. `registry.guide`가 가리키는 장부 가이드의 작업 색인과 공통 규칙을 읽는다.

상대 장부 경로는 설정 원본 파일이 있는 디렉터리를 기준으로 해석한다.
초기화가 필요하면 `wk-work`가 `wk-setup-workspace`를 선택한다.
초기화 결과가 준비되기 전에는 그 설정에 의존하는 장부 쓰기를 진행하지 않는다.

### 연결 워크트리의 설정

1. `git worktree list --porcelain`으로 Git 기본 작업공간을 확인한다.
2. 기본 작업공간의 대응 프로젝트 설정과 기존 장부를 확인한다.
3. 기존 구현 작업공간이면 소유 작업에 기록된 설정 원본·저장소·경로와 대조한다.
4. 기록된 원본으로 같은 장부를 확인할 수 있으면 그 원본을 사용한다.

| 조건 | 처리 |
| --- | --- |
| 연결 워크트리에 설정이 없다. | 기본 작업공간의 설정 원본을 사용한다. |
| 설정 후보가 갈리거나 원본이 불분명해 기록으로 확정할 수 없다. | 초기화·이후 설정 읽기를 멈추고 후보·확인한 근거·필요한 원본 선택을 반환한다. |

같은 소유 작업의 장부를 워크트리 안에 별도로 복제하지 않는다.
사용자 판단이 필요한 경우에는 [자율 진행과 사용자 판단](../policies/progression.md#자율-진행과-사용자-판단)에 따라 질문 주체와 필요 여부를 정한다.

## 작업 식별

- 작업 폴더는 `<registry.root>/work/<WORK_ID>`다.
- 같은 목표의 작업이 있으면 기존 작업을 사용한다.
- 후보가 여러 개라 선택할 수 없으면 후보의 목표·범위와 필요한 작업 선택을 반환한다.
- 새 작업 ID는 `work.id_prefix` 뒤에 네 자리 일련번호를 붙인다.
- 기존 작업 ID를 확인한 뒤 사용하지 않은 다음 번호를 선택한다.
- 예를 들어 접두사가 `MIM`이면 첫 작업 ID는 `MIM0001`이다.
- 새 작업 폴더가 이미 있으면 덮어쓰지 않고 작업 ID를 다시 확인한다.

## 문서 관리

- 작업을 생성·분해할 때는 [작업 단위와 용어](work-model.md#작업-단위와-용어)를 확인한다.
- 작업 생성·기록 갱신 전에는 [현재 기록](work-model.md#현재-기록)과 작성할 항목의 정의를 읽는다.
- 단계·상태를 기록할 때는 [단계와 상태](work-model.md#단계와-상태), 완료를 판정하면 [완료 판정](work-model.md#완료-판정)을 읽는다.
- 새 작업이면 작업 폴더 루트에 `work.md`와 최초 이력이 담긴 `history.md`를 만든다.
- 기존 작업을 재개할 때는 두 파일을 먼저 읽는다.
- 기존 작업에 `history.md`가 없으면 현재 확인한 상태를 첫 이력으로 기록한다.
- `work.md`에는 현재 상태와 [현재 이해](work-model.md#현재-이해)의 요약을 둔다.
- 기존 작업 ID·관계·이력·산출물 링크는 완료·취소 후에도 유지한다.

## 산출물 저장

### 범위와 경로

- 독립적으로 보존할 현상·진단·비교·결정·계약·계획·검토·검증 결과는 길이와 무관하게 별도 파일로 저장한다.
- 함께 검토하고 재사용할 결정·계약·계획은 한 산출물의 구분된 항목으로 보존할 수 있다.
- 보존할 원시 자료·로그·JSON·이미지에도 같은 규칙을 적용한다.
- 단순 상태 갱신·다음 행동·번호 예약은 별도 산출물 파일로 만들지 않는다.
- 탐색 중인 가설·비교·다음 질문은 `work.md`의 현재 이해에서 갱신한다.
- 독립적인 검토·결정·인계에 사용할 결과가 되면 해당 근거를 별도 산출물로 확정한다.
- 조사 회차마다 같은 내용을 새 보고서로 복제하지 않는다.
- 코드·테스트·공식 제품 문서는 기존 제품 경로를 사용한다.

새 산출물의 경로는 `<registry.root>/work/<WORK_ID>/<yymmdd>/<NNN>_<이름>.<확장자>`다.
`이름`은 용도를 나타내며 `plan`, `diagnosis`, `verification.stdout`처럼 정한다.

### 날짜와 순번 할당

작업 기록 담당자 한 명이 해당 작업의 날짜·순번을 직렬로 할당한다.
다른 작성자는 배정받은 경로만 사용한다.
이미 경로를 배정받았으면 예약과 담당자를 확인한 뒤 그 경로를 사용한다.
다음 절차는 새 경로가 필요할 때만 수행한다.

1. 기록 담당자의 로컬 날짜로 `yymmdd`를 정한다.
2. 해당 작업·날짜의 사용 번호와 `history.md`의 예약 번호를 확인한다.
3. 가장 큰 번호 다음을 세 자리로 할당한다. 첫 번호는 `001`이다.
4. 예약 시각·시간대·경로·용도·작성자를 `history.md`에 남긴다.
5. 같은 번호의 다른 파일·예약이나 기존 대상 경로가 있는지 확인한다.
6. 충돌이 없으면 기존 파일을 덮어쓰지 않는 방식으로 새 파일을 만든다.

- 날짜가 바뀌면 그 날짜 폴더의 사용·예약 번호를 기준으로 다시 계산한다.
- 배정된 경로는 작성 중 날짜가 바뀌어도 이동하지 않는다.
- 파일마다 다른 번호를 사용한다. 한 검증의 보고서·로그·JSON도 각각 할당한다.
- 취소·실패·미작성 예약 번호는 재사용하지 않는다. 빈 번호를 채우려고 재정렬하지 않는다.
- 다음 번호가 `999`를 넘으면 할당을 멈추고 저장 규칙 변경의 필요성과 영향을 반환한다.
- 경로나 번호가 충돌하면 기존 파일을 덮어쓰지 않고 할당 상태를 다시 확인한다.

순번은 산출물의 예약·등록 순서다.
실제 실행 시각·의존 관계·검증 근거를 대신하지 않는다.

### 확정·수정·참조

- 작성 중인 파일은 배정된 작성자가 이어서 작성할 수 있다.
- 작성자는 작업 기록 담당자에게 실제 경로와 확인 근거를 반환한다.
- 작성 완료로 기록한 파일은 덮어쓰거나 이름을 바꾸지 않는다.
- 수정본은 새 번호로 저장하고 이전 산출물을 연결한다.
- 필요한 검토·승인 전에는 수정본을 대기로 표시하고 기존 유효본을 유지한다.
- 승인 필요 여부는 [자율 진행과 사용자 판단](../policies/progression.md#자율-진행과-사용자-판단)을 따른다.
- 기존본도 사실·버전 변경으로 무효하면 사유를 기록한다.
- 대체할 유효본이 없으면 그 사실을 명시한다.
- 유효본을 바꿀 때는 대상 경로·버전과 필요한 확인·승인 근거를 남긴다.
- 이전 산출물의 만료·대체 여부는 `work.md`와 `history.md`에 기록한다.
- 사용할 유효한 산출물은 `work.md`에 명시한다. 가장 큰 번호를 자동 선택하지 않는다.
- 링크는 링크를 쓰는 문서의 위치를 기준으로 만든다.
- 기존 산출물은 이동·이름 변경 없이 재사용한다. 새로 생성하는 산출물부터 이 규약을 적용한다.

## 색인 관리

- 장부 가이드에는 작업 ID·제목·`work.md` 링크·상위 작업을 색인한다.
- 단계와 상태의 원본은 각 작업의 `work.md`다.
- 포함 관계의 원본은 하위 작업 `work.md`의 상위 작업 필드다.
- 작업 생성·포함 관계 변경 시 [포함 관계](work-model.md#포함-관계) 규칙을 적용한다.
- 그 결과를 장부 가이드의 색인에 반영한다.
- 색인과 원본이 다르면 실제 작업 기록을 확인한 뒤 불일치를 바로잡는다.

## 기록 갱신

이 절차는 작업 기록 담당자가 수행한다.

1. 공유 문서의 현재 작성자를 확인한다.
2. 다른 작성자가 맡은 파일이면 수정 전에 조율한다.
3. 아직 보존하지 않은 독립 산출물이 있으면 [산출물 저장](#산출물-저장) 절차로 보존한다.
4. 진척이 생기면 `work.md`에 현재 사실과 실제 산출물 링크를 반영한다.
5. `history.md`에 날짜·작성자·변경 내용·확인 근거·남은 질문이나 다음 행동을 시간순으로 추가한다.

이전 이력을 덮어쓰지 않는다.

## 기존 기록과 호환

- 새 필드는 지금 다루는 작업에만 보완한다.
- 원작업·관련 작업 링크만으로 포함 관계나 선행 의존성을 추정하지 않는다.
- 기존 완료 표기는 [완료 판정](work-model.md#완료-판정)에 따라 확인한다.
- 근거가 부족하면 부족한 부분을 미확인으로 기록한다.
- 기존 장부 전체를 새 형식으로 일괄 변환하지 않는다.
