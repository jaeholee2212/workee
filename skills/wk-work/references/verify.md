# 검증

결과를 계약·원래 목표·완료 조건과 대조한다.

## 시작 조건

- 현재 작업의 완료 조건과 원래 관찰 근거를 읽는다.
- 검증할 산출물의 종류·위치·버전을 확인한다.
- 구현 작업공간이 등록돼 있으면 소유 작업의 워크트리·브랜치·미커밋 변경을 확인한다.
- 공간 기록이 없는 기존 작업은 현재 검증 대상의 위치를 명시한다.

## 진행

1. 산출물 종류에 맞는 방법으로 근거를 확인한다.
2. 통합 예정이거나 별도 검토가 필요한 변경은 [wk-review](../../wk-review/SKILL.md)로 검토한다.
3. 아래 통합 조건을 모두 충족한 경우에만 [wk-integrate](../../wk-integrate/SKILL.md)로 반영한다.
4. 반영 결과에 [검증 근거](work-model.md#검증-근거)의 유효성 규칙을 적용한다.

| 산출물 종류 | 확인 방법 |
| --- | --- |
| 구현 결과 | [wk-verify](../../wk-verify/SKILL.md)로 실제 사용 지점의 동작을 확인한다. |
| 연구·논의 결과 | 합의한 질문에 대한 답을 출처와 대조한다. |

통합 조건:

- 최상위 구현 작업의 대상 브랜치 반영이다.
- 현재 요청 범위에 통합이 포함돼 있다.
- 필수 검증과 검토가 통과했다.
- 통합 대상·방법·범위가 승인됐다.

검토 담당자는 검토 파일만 갱신한다.

## 산출물

- 완료 조건별 [검증 판정](work-model.md#검증-근거)
- 대상 위치·브랜치·버전과 검사 환경
- 확인 방법·실제 결과·근거 링크
- 미검증 범위와 남은 행동

## 전환·중단

| 조건 | 다음 행동 |
| --- | --- |
| 구현이 계약을 지키지 못한다. | 영향받은 변경을 구현으로 되돌린다. |
| 계약이나 범위가 불명확하다. | 해당 부분을 논의나 계획으로 되돌린다. |
| 환경·권한·근거가 부족하다. | 검증 근거에 확인하지 못한 범위와 재개 조건을 남긴다. |
| 통합 승인이 남았다. | 승인 대기와 다음 행동을 기록한다. |
