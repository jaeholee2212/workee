# 계획

합의한 목표를 실행·검증 가능한 결과 단위로 나눈다.

## 시작 조건

- 현재 작업의 문제·범위·완료 조건·결정을 읽는다.
- 유효한 계약과 기존 계획을 확인한다.

## 진행

1. 동작의 약속이 부족하면 [wk-contract](../../wk-contract/SKILL.md)로 필요한 계약을 정한다.
2. [wk-plan](../../wk-plan/SKILL.md)으로 작업 구조와 첫 변경을 계획한다.
3. 작업 구조를 바꾸면 [장부 규약](registry.md)에 따라 등록한다.
4. 여러 작성자나 공유 자원이 있으면 [wk-coordinate](../../wk-coordinate/SKILL.md)로 조정한다.
5. 계획한 하위 결과의 기여와 합류 검사를 전체 완료 조건에 대조한다.

## 산출물

- 현재 작업의 목표·범위·전체 완료 조건
- 하위 작업이 있으면 작업 ID·기여할 결과·각 완료 조건
- 각 변경의 허용 범위와 검사 방법
- 선행 산출물의 제공 작업·준비 조건·소비 시점
- 하위 결과의 합류 방법과 전체 검증 방법
- 구현 작업공간의 소유 작업과 기준·통합 대상 후보
- 첫 실행 후보와 남은 승인·미정

## 전환·중단

| 조건 | 다음 행동 |
| --- | --- |
| 조사나 중요한 결정이 더 필요하다. | 해당 부분을 논의로 되돌린다. |
| 필요한 계약과 실행 범위가 승인됐다. | 첫 실행 후보의 구현으로 진행할 수 있다. |
