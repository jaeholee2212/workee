# 계획

선택한 방향을 검토된 설계와 실행·검증 가능한 결과 단위로 바꾼다.

## 시작 조건

- 현재 작업의 문제·범위·완료 조건·결정을 읽는다.
- 유효한 계약·기존 계획과 [현재 이해](work-model.md#현재-이해)를 확인한다.
- [탐색 규약](exploration.md)을 읽는다.

## 진행

1. [wk-plan](../../wk-plan/SKILL.md)의 설계 구체화로 구현 방식과 사용 흐름을 검토한다.
2. 설계의 결정 준비를 막는 미정은 [탐색 반복](exploration.md#탐색-반복)으로 조사한다.
3. 관찰 가능한 동작이 정해지면 [wk-contract](../../wk-contract/SKILL.md)로 계약을 갱신한다.
4. 설계와 계약이 결정 준비를 충족하면 `wk-plan`의 작업 분해와 첫 실행을 정한다.
5. 작업 구조를 바꾸면 [장부 규약](registry.md)에 따라 등록한다.
6. 여러 작성자나 공유 자원이 있으면 [wk-coordinate](../../wk-coordinate/SKILL.md)로 조정한다.
7. 설계의 위험이나 논쟁이 남으면 [wk-review](../../wk-review/SKILL.md)로 별도 검토한다.
8. 하위 결과와 합류 검사가 원래 문제의 완료 조건을 충족하는지 확인한다.

기존 계약과 설계는 유효한 부분을 재사용한다.
새 근거로 방향이나 계약이 바뀌면 영향받는 부분부터 다시 검토한다.
계획 요청에 필요한 논의 재진입은 같은 요청 범위에서 이어 간다.

## 산출물

- 현재 작업의 목표·범위·전체 완료 조건
- 구현 방식의 선택 근거와 책임·데이터·상태·효과의 경계
- 주요 사용 사례와 실패 상황의 흐름, 유효한 동작 계약
- 하위 작업이 있으면 작업 ID·기여할 결과·각 완료 조건
- 각 변경의 허용 범위와 검사 방법
- 선행 산출물의 제공 작업·준비 조건·소비 시점
- 하위 결과의 합류 방법과 전체 검증 방법
- 구현 작업공간의 소유 작업과 기준·통합 대상 후보
- 첫 실행 후보, 남은 위험과 재검토 조건

## 완료 근거

- 설계의 [결정 준비](exploration.md#결정-준비)가 충족됐다.
- 중요한 사용 사례와 실패 상황이 설계·계약·검사 방법에 연결된다.
- 첫 실행의 선행 조건과 하위 결과의 합류 방법이 확인됐다.
- 원래 문제의 해결을 판정할 전체 검증 방법이 있다.

조사만 계획한 상태는 구현 가능한 계획과 구분한다.

## 전환·중단

| 조건 | 다음 행동 |
| --- | --- |
| 문제나 방향을 바꿀 근거가 발견됐다. | 영향받는 부분을 논의로 되돌려 조사한다. |
| 설계나 동작 계약의 결정 준비를 막는 미정이 남았다. | 제품 구현 전에 해당 조사를 실행한다. |
| 설계의 결정 준비와 실행 계획의 완료 조건이 충족됐다. | 구현이 요청 범위에 있으면 첫 실행을 시작한다. |
| 사용자 판단·근거 접근·실행 한도 때문에 진행할 수 없다. | [탐색 종료](exploration.md#탐색-종료)를 적용한다. |

계획만 요청받았으면 설계 근거와 실행 계획을 응답한다.
