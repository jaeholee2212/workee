# 구현

승인된 계약과 변경 범위 안에서 작은 결과를 완성한다.

## 시작 조건

- 현재 작업의 계약·계획·승인된 변경 범위를 읽는다.
- 마스터 작업만 지정됐으면 실행 가능한 하위 작업과 그 승인 범위를 확인한다.
- 선행 산출물이 필요한 행동과 소비 조건을 확인한다.

## 진행

1. [wk-worktree](../../wk-worktree/SKILL.md)로 소유 작업의 브랜치·워크트리를 준비하거나 확인한다.
2. 해당 워크트리에서 선행 산출물의 준비 여부를 확인한다.
3. 파일·외부 자원의 쓰기가 겹치면 [wk-coordinate](../../wk-coordinate/SKILL.md)로 조정한다.
4. 해당 워크트리에서 [wk-build](../../wk-build/SKILL.md)로 검사와 최소 변경을 반복한다.
5. 변경에 영향받은 [검증 근거](work-model.md#검증-근거)의 유효성을 갱신한다.

작업공간 준비 전에는 제품·테스트를 변경하지 않는다.
원본 작업공간의 브랜치를 바꾸는 대신 준비한 워크트리를 실행 위치로 사용한다.

## 산출물

- 실제 변경과 대상 버전
- 실행 위치·브랜치와 검사 결과
- 관련 산출물과 검증 근거
- 남은 실패·미정·대기 사유와 다음 행동

## 전환·중단

| 조건 | 다음 행동 |
| --- | --- |
| 필요한 작업공간이나 선행 산출물이 준비되지 않았다. | 해당 행동의 대기 사유와 재개 조건을 기록한다. |
| 다른 승인된 행동은 진행할 수 있다. | 그 행동의 선행 조건을 따로 확인한다. |
| 구현이 계약을 충족하지 못한다. | 같은 변경 단위에서 검사와 구현을 계속한다. |
| 새 동작 결정이나 계약 보완이 필요하다. | 영향받는 부분을 논의나 계획으로 되돌린다. |
| 승인된 변경 단위의 검사가 통과했다. | 검증으로 진행할 수 있다. |
