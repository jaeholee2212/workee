# 계획 조율

선택한 방향에서 설계·계약·실행 계획을 조합한다.
문제·완료 조건·방향과 기존 계약·설계를 입력으로 사용한다.
[진행 정책](../policies/progression.md)에 따라 부족한 근거의 조사를 이어 간다.

## 스킬 조합

| 필요한 결과 | 실행할 스킬과 요청 | 다음 선택에 사용할 반환값 |
| --- | --- | --- |
| 설계 초안이나 수정안 | [wk-plan](../../wk-plan/SKILL.md)에 설계 구체화를 요청한다. | 책임·데이터·상태·효과의 경계, 사용 흐름·설계 미정 |
| 구현 방식의 차이 | [wk-compare](../../wk-compare/SKILL.md)에 설계 후보 비교를 맡긴다. | 대안별 근거·비용·반례 |
| 설계 가정의 확인 | [wk-diagnose](../../wk-diagnose/SKILL.md)에 가정을 판별할 조사를 맡긴다. | 확인된 근거·남은 가정 |
| 설계의 준비 판정과 선택 | [wk-decide](../../wk-decide/SKILL.md)에 설계 선택을 맡긴다. | 준비 여부·결정·사용자 판단 필요 여부 |
| 관찰 가능한 동작의 약속 | [wk-contract](../../wk-contract/SKILL.md)에 계약 작성을 맡긴다. | 동작·실패 경계·호환성·미정 |
| 실행·검증할 결과 단위 | [wk-plan](../../wk-plan/SKILL.md)에 준비된 설계·계약으로 실행 계획을 요청한다. | 작업 구조·선행 조건·첫 실행·전체 검증 |
| 작성 범위와 자원 배정 | [wk-coordinate](../../wk-coordinate/SKILL.md)에 여러 작성자나 공유 자원의 조정을 맡긴다. | 배정·충돌·대기 조건 |
| 설계·계획에 대한 별도 검토 | [wk-review](../../wk-review/SKILL.md)에 유효한 설계·계약·계획을 전달한다. | 검토 판정·보완 근거 |

설계 구체화와 실행 계획은 `wk-plan`에 요청할 서로 다른 결과다.
설계와 계약이 준비되기 전에는 실행 계획을 확정하지 않는다.
설계·계약에서 돌아온 미정은 비교·진단·결정 중 필요한 스킬로 보낸다.
작업 구조가 확정되면 [장부 규약](../references/registry.md)에 따라 등록한다.
새 근거가 방향을 바꾸면 [논의](discuss.md)로 돌아간다.
이 복귀가 요청한 계획에 필요하면 추가 진행 지시를 기다리지 않는다.

## 단계 완료와 전환

- 설계 선택의 준비 판정과 결정 근거가 유효하다.
- 계약과 실행 계획이 각각 자기 완료 기준을 충족했다.
- 계획의 결과·검사·합류 방법이 원래 완료 조건에 연결돼 있다.
- 남은 위험에 수용 근거가 있고 실행을 막는 선행 미정은 구분돼 있다.

| 반환된 결과 | 조율 행동 |
| --- | --- |
| 문제나 방향의 근거가 바뀌었다. | 논의의 해당 결과부터 다시 배정한다. |
| 설계·계약·계획에 중요한 보완이 필요하다. | 해당 결과를 만드는 스킬을 다시 실행한다. |
| 계획 단계의 완료 조건을 충족했다. | 구현이 요청 범위에 있으면 [구현](implement.md)으로 이어 간다. |
| 진행 정책의 종료 조건에 해당한다. | [종료와 재개](../policies/progression.md#종료와-재개)를 적용한다. |

계획만 요청받았으면 설계 근거와 실행 계획을 응답한다.
조건부 계획은 구현 가능한 계획과 구분한다.
