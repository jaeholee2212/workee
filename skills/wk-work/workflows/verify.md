# 검증 조율

원래 문제·완료 조건과 검증할 산출물의 위치·버전을 입력으로 사용한다.
검증 범위가 변경 단위인지 전체 목표인지 먼저 정한다.
[진행 정책](../policies/progression.md)에 따라 검증·검토·필요한 통합을 조합한다.

## 스킬 조합

| 필요한 결과 | 실행할 스킬과 요청 | 다음 선택에 사용할 반환값 |
| --- | --- | --- |
| 완료 조건별 검증 | [wk-verify](../../wk-verify/SKILL.md)에 구현 또는 연구·논의·계획 산출물을 전달한다. | 조건별 판정·실제 근거·미검증 범위 |
| 별도 적합성 검토 | [wk-review](../../wk-review/SKILL.md)에 대상 버전과 검토 범위를 전달한다. | 검토 판정·의견·추가 확인 |
| 결정 준비의 재평가 | [wk-decide](../../wk-decide/SKILL.md)에 선택을 바꿀 새 근거를 전달한다. | 기존 결정의 유효성·부족한 근거 |
| 검증된 후보의 로컬 커밋 | [wk-commit](../../wk-commit/SKILL.md)에 후보와 유효한 단위 검증·필요한 검토 근거를 전달한다. | 실제 SHA·부모·트리·동일성 판정·남은 변경 |
| 승인된 대상 반영 | [wk-integrate](../../wk-integrate/SKILL.md)에 통합 대상·범위·유효한 검증과 검토를 전달한다. | 반영 버전·남은 검증 |

통합 예정이거나 중요한 별도 검토가 필요하면 `wk-review`를 배정한다.
검토 의견은 수정·기각·추가 확인에 맞는 작업으로 연결한다.
수정이나 통합으로 대상이 바뀌면 영향받은 검증·검토를 다시 배정한다.
논의·계획의 근거 검증 결과와 [공동 검토·실행 위임](../references/work-model.md#공동-검토와-실행-위임)의 충족 여부는 별도로 확인한다.
검증 통과만으로 미합의 계획의 제품 구현을 배정하지 않는다.

## 변경 단위 검증과 커밋

1. 준비된 [커밋 후보](../references/work-model.md#커밋-후보)의 부모·트리·범위·검증 위치를 확인한다.
2. `wk-verify`에 해당 후보와 변경 단위의 완료 조건을 전달한다.
3. 별도 검토가 필요한 변경이면 같은 후보를 `wk-review`에 배정한다.
4. 로컬 커밋이 허용되고 필수 검증과 필요한 검토가 유효하게 통과했으면 `wk-commit`에 커밋 생성을 요청한다.
5. 반환된 실제 SHA와 후보의 동일성 판정을 확인한다.
6. 일치가 확인되면 해당 커밋과 검증 근거를 작업 기록에 연결한다.

- 필수 조건의 실패·판단 불가·미실행이 남으면 해당 후보의 커밋을 배정하지 않는다.
- 후보가 바뀌면 `wk-commit`에 새 후보 준비를 요청한다.
- 새 후보의 검증은 `wk-verify`에 다시 배정한다.
- 후크나 동시 변경으로 실제 커밋이 후보와 다르면 검증된 커밋으로 채택하지 않는다.
- 불일치가 발생하면 실제 SHA·변경·남은 근거를 보존한 뒤 보완을 배정한다.
- 재시도 전에는 이미 생성된 커밋이 있는지 반환 근거로 확인한다.
- 단위 커밋만으로 작업을 done으로 바꾸지 않는다.
- 커밋이 요청에서 제외됐으면 검증 근거를 보존하고 다음 허용된 행동을 진행한다.

## 합류 결과 검증

필수 구현 결과가 준비되면 `wk-work`가 전체 목표에 대해 다음 확인을 조율한다.

1. 필수 결과가 공유 작업공간에 실제 반영됐는지 확인한다.
2. 검증 대상에 영향을 주는 구현·연결 작업의 쓰기 종료를 확인한다.
3. 합쳐진 결과의 커밋 SHA와 남은 미커밋 변경을 식별한다.
4. `wk-verify`에 해당 결과와 원래 목표의 전체 완료 조건을 전달한다.
5. 필요한 별도 검토는 구현자와 다른 관점으로 `wk-review`에 배정한다.
6. 실패나 누락은 영향받는 구현·설계에 돌려보낸다.

개별 실행자의 완료 응답만으로 전체 통과를 판정하지 않는다.
검증 중 관련 쓰기가 발생하면 영향받은 근거를 만료로 표시한다.
유효한 전체 검증 결과를 받을 때까지 필요한 보완과 검증을 이어 간다.
전체 검증 중 추가 수정이 생기면 해당 수정의 후보 검증·커밋과 영향받은 전체 검증을 이어 간다.
합의한 동작 안의 보완은 기존 실행 위임으로 진행한다.
핵심 전제·사용자 동작·범위·주요 비용을 바꿔야 하면 영향받는 부분의 [공동 검토](../policies/collaboration.md)를 다시 연다.

## 통합 진입 조건

- 최상위 구현 작업의 대상 브랜치 반영이다.
- 현재 요청 범위에 통합이 포함돼 있다.
- 필수 검증과 검토가 유효하게 통과했다.
- 반영할 구현·테스트·제품 문서가 검증된 커밋에 포함돼 있다.
- 통합 대상·방법·범위가 승인돼 있다.

조건이 모두 충족될 때만 통합을 배정한다.
단계 전환을 통합·푸시 등 별도 행동의 승인으로 해석하지 않는다.

## 단계 완료와 전환

| 반환된 결과 | 조율 행동 |
| --- | --- |
| 구현이 계약을 충족하지 못한다. | 영향받은 변경을 [구현](implement.md)으로 돌린다. |
| 계약·설계가 불명확하거나 원래 문제가 남는다. | 해당 부분을 [논의](discuss.md)나 [계획](plan.md)으로 돌린다. |
| 추가 근거로 확인할 수 있는 조건이 남았다. | 해당 조사·검증을 다시 배정한다. |
| 변경 단위의 커밋이 완료됐고 남은 구현이 있다. | [구현](implement.md)으로 돌아가 다음 단위를 진행한다. |
| 모든 필수 구현과 허용된 커밋이 완료됐다. | 합쳐진 결과의 전체 목표 검증을 배정한다. |
| 전체 목표의 검증·검토·필요한 통합이 끝났다. | [전체 완료 판정](../references/work-model.md#완료-판정)을 적용한다. |
| 진행 정책의 종료 조건에 해당한다. | [종료와 재개](../policies/progression.md#종료와-재개)를 적용한다. |

하위 스킬의 완료 보고와 원래 목표의 달성을 구분한다.
조건별 근거와 남은 범위를 종합해 전체 결과를 응답한다.
