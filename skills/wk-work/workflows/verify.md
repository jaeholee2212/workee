# 검증 조율

원래 문제·완료 조건과 검증할 산출물의 위치·버전을 입력으로 사용한다.
[진행 정책](../policies/progression.md)에 따라 검증·검토·필요한 통합을 조합한다.

## 스킬 조합

| 필요한 결과 | 실행할 스킬과 요청 | 다음 선택에 사용할 반환값 |
| --- | --- | --- |
| 완료 조건별 검증 | [wk-verify](../../wk-verify/SKILL.md)에 구현 또는 연구·논의·계획 산출물을 전달한다. | 조건별 판정·실제 근거·미검증 범위 |
| 별도 적합성 검토 | [wk-review](../../wk-review/SKILL.md)에 대상 버전과 검토 범위를 전달한다. | 검토 판정·의견·추가 확인 |
| 결정 준비의 재평가 | [wk-decide](../../wk-decide/SKILL.md)에 선택을 바꿀 새 근거를 전달한다. | 기존 결정의 유효성·부족한 근거 |
| 승인된 대상 반영 | [wk-integrate](../../wk-integrate/SKILL.md)에 통합 대상·범위·유효한 검증과 검토를 전달한다. | 반영 버전·남은 검증 |

통합 예정이거나 중요한 별도 검토가 필요하면 `wk-review`를 배정한다.
검토 의견은 수정·기각·추가 확인에 맞는 작업으로 연결한다.
수정이나 통합으로 대상이 바뀌면 영향받은 검증·검토를 다시 배정한다.

## 합류 결과 검증

구현을 분담했으면 `wk-work`가 다음 확인을 조율한다.

1. 필수 결과가 공유 작업공간에 실제 반영됐는지 확인한다.
2. 검증 대상에 영향을 주는 구현·연결 작업의 쓰기 종료를 확인한다.
3. 합쳐진 결과의 대상 버전과 미커밋 변경을 식별한다.
4. `wk-verify`에 해당 결과와 원래 목표의 전체 완료 조건을 전달한다.
5. 필요한 별도 검토는 구현자와 다른 관점으로 `wk-review`에 배정한다.
6. 실패나 누락은 영향받는 구현·설계에 돌려보낸다.

개별 실행자의 완료 응답만으로 전체 통과를 판정하지 않는다.
검증 중 관련 쓰기가 발생하면 영향받은 근거를 만료로 표시한다.
유효한 전체 검증 결과를 받을 때까지 필요한 보완과 검증을 이어 간다.

## 통합 진입 조건

- 최상위 구현 작업의 대상 브랜치 반영이다.
- 현재 요청 범위에 통합이 포함돼 있다.
- 필수 검증과 검토가 유효하게 통과했다.
- 통합 대상·방법·범위가 승인돼 있다.

조건이 모두 충족될 때만 통합을 배정한다.
단계 전환을 통합·푸시 등 별도 행동의 승인으로 해석하지 않는다.

## 단계 완료와 전환

| 반환된 결과 | 조율 행동 |
| --- | --- |
| 구현이 계약을 충족하지 못한다. | 영향받은 변경을 [구현](implement.md)으로 돌린다. |
| 계약·설계가 불명확하거나 원래 문제가 남는다. | 해당 부분을 [논의](discuss.md)나 [계획](plan.md)으로 돌린다. |
| 추가 근거로 확인할 수 있는 조건이 남았다. | 해당 조사·검증을 다시 배정한다. |
| 요청한 범위의 검증·검토·필요한 통합이 끝났다. | [전체 완료 판정](../references/work-model.md#완료-판정)을 적용한다. |
| 진행 정책의 종료 조건에 해당한다. | [종료와 재개](../policies/progression.md#종료와-재개)를 적용한다. |

하위 스킬의 완료 보고와 원래 목표의 달성을 구분한다.
조건별 근거와 남은 범위를 종합해 전체 결과를 응답한다.
