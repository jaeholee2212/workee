# 구현 조율

유효한 계약·계획과 실행을 맡긴 변경 범위를 입력으로 사용한다.
실행할 결과와 그 선행 산출물을 선택한다.
[결과에 따른 반복](../policies/progression.md#결과에-따른-반복)으로 준비·작성·변경 단위 검증·로컬 커밋을 조합한다.

## 구현 진입

- [합의와 실행 위임](../policies/progression.md#합의와-실행-위임)으로 유효성을 판단한 [계획·범위·위임 기록](../references/work-model.md#공동-검토와-실행-위임)을 실제 배정과 대조한다.
- 필요한 합의나 실행 위임이 없으면 작업공간 생성과 제품 변경에 앞서 [계획](plan.md)의 공동 검토로 돌아간다.

## 스킬 조합

| 필요한 결과 | 실행할 스킬과 요청 | 다음 선택에 사용할 반환값 |
| --- | --- | --- |
| 구현 작업공간 | [wk-worktree](../../wk-worktree/SKILL.md)에 생성이나 재사용 확인을 요청한다. | 준비된 경로·브랜치·기준·불일치 |
| 작성 범위와 공유 자원 조정 | [wk-coordinate](../../wk-coordinate/SKILL.md)에 실행자와 충돌 조정을 맡긴다. | 배정·실행 가능한 범위·대기 조건 |
| 변경과 해당 검사 | [wk-build](../../wk-build/SKILL.md)에 준비된 작업공간·계약·변경 단위를 전달한다. | 실제 변경·대상 버전·검사 결과·새 미정 |
| 검증할 커밋 후보 | [wk-commit](../../wk-commit/SKILL.md)에 선택한 변경 단위의 후보 준비를 요청한다. | 부모·트리·포함 범위·검증 위치·남은 준비 조건 |

작업공간과 필요한 선행 산출물이 준비된 결과만 구현에 배정한다.
한 행동이 대기해도 다른 승인된 결과를 실행할 수 있으면 그 결과를 배정한다.
검사와 수정의 내부 반복은 `wk-build`가 수행한다.
반환된 변경으로 영향받는 이전 검증·검토 근거를 만료로 표시한다.

## 실행자 선택

`wk-work`는 구현을 배정할 때 서브에이전트 사용 가능 여부와 계획의 결과 단위를 확인한다.
독립적으로 구현·검사할 수 있고 분담의 이점이 있는 결과는 서브에이전트에 적극 위임한다.
준비된 결과를 동시에 실행할 수 있는지는 `wk-coordinate`의 배정과 충돌 근거로 판단한다.

- 작거나 강하게 결합돼 분담 비용이 더 큰 변경은 `wk-work`를 수행하는 에이전트가 `wk-build`로 직접 처리한다.
- 독립적인 결과라도 필요한 선행 산출물이 준비되기 전에는 구현을 시작시키지 않는다.
- 도구나 동시 실행 한도가 부족하면 준비된 결과를 직접 처리하거나 실행 여유가 생기는 순서로 배정한다.
- 에이전트 수를 늘리기 위해 계획의 결과 단위를 억지로 쪼개지 않는다.

## 위임과 진행 추적

1. 위임할 결과의 파일·계약·공유 자원 범위를 `wk-coordinate`에 전달한다.
2. 반환된 배정에 맞춰 사용 가능한 서브에이전트 도구로 실행자를 생성하거나 재사용한다.
3. 각 실행자에게 아래 입력과 `wk-build`의 실행을 요청한다.
4. [현재 기록](../references/work-model.md#현재-기록)에 실행자와 배정한 결과를 연결한다.
5. 실행자의 진척·차단 사유·완료 응답을 도구로 확인한다.
6. 반환된 근거에 따라 다음 배정이나 필요한 보완을 정한다.

| 전달할 입력 | 내용 |
| --- | --- |
| 목표와 계약 | 맡은 결과·완료 조건·유효한 설계·계약·변경 계획·실행 위임 범위 |
| 실행 위치와 근거 | 공유 워크트리·설정 원본·선행 산출물의 위치와 준비 근거 |
| 작성 권한 | 담당 파일·공유 자원·기록 경로·제외 범위 |
| 검사와 반환 | 해당 검사 방법·반환할 변경과 근거·남은 미정·쓰기 종료 여부 |

다른 실행자가 같은 공간에서 작업한다는 사실을 각 실행자에게 알린다.
다른 작성자의 변경을 보존하도록 요청한다.
추가 실행자나 배정 범위 변경이 필요하면 `wk-work`에 근거를 반환하도록 요청한다.

- 위임한 파일은 해당 실행자에게 맡긴다.
- 기다리는 동안에는 배정과 겹치지 않는 구현이나 합류 준비를 진행한다.
- 완료를 기다릴 때는 환경이 제공하는 상태 변화 대기를 우선한다.
- 실행 가능한 선행 조건이 충족되면 다음 결과를 추가 지시 없이 배정한다.
- 한 실행자가 막히면 그 결과에 의존하는 행동만 대기시킨다.
- 진행 중인 쓰기의 충돌이 확인되면 해당 실행자에게 중단을 요청한다.
- 충돌한 쓰기의 중단을 확인한 뒤 `wk-coordinate`에 배정 조정을 맡긴다.
- 사용자 판단이 필요하면 [진행 정책](../policies/progression.md#자율-진행과-사용자-판단)을 적용한다.

## 결과 회수와 합류

1. 실행자별 [스킬 실행 결과](../references/work-model.md#스킬-실행-결과)를 받는다.
2. 보고된 변경 파일·대상 버전·검사 근거를 공유 작업공간의 실제 결과와 대조한다.
3. 실패·중단된 실행은 남은 변경과 진행 중인 쓰기를 확인한다.
4. 담당자를 바꿔야 하면 기존 실행자의 중단을 확인한 뒤 `wk-coordinate`에 재배정을 맡긴다.
5. 결과를 연결하는 변경이 필요하면 담당 범위를 배정해 `wk-build`로 수행한다.
6. 의미 있는 변경 단위가 준비되면 아래 로컬 커밋 절차를 진행한다.

응답 지연만으로 실행자의 종료를 추정하지 않는다.
회수되지 않은 필수 결과가 있으면 전체 작업을 완료 처리하지 않는다.
서브에이전트의 검사 통과를 합류 결과의 전체 검증으로 대신하지 않는다.

## 합의에 영향을 주는 발견

새 근거가 합의에 영향을 주면 [합의 변경과 재검토](../policies/progression.md#합의-변경과-재검토)로 대기·계속·재개할 범위를 정한다.
그 결과를 구현·커밋의 배정에 반영한다.

## 변경 단위와 로컬 커밋

1. 계획의 잠정 커밋 단위와 회수한 결과의 실제 의존성을 대조한다.
2. 필요한 구현·테스트·제품 문서를 포함하는 변경 단위를 선택한다.
3. 단독으로 성립하지 않는 변경은 필요한 결과와 묶거나 선행 커밋 뒤로 배정한다.
4. `wk-coordinate`에 Git 쓰기 담당자와 후보 검증 위치의 배정을 맡긴다.
5. `wk-commit`에 포함·제외 범위와 해당 단위의 필수 검증 조건을 전달한다.
6. 준비된 [커밋 후보](../references/work-model.md#커밋-후보)를 [변경 단위 검증](verify.md#변경-단위-검증과-커밋)으로 보낸다.

- 같은 작업 브랜치의 후보 준비·검증·커밋은 한 경로씩 진행한다.
- 격리된 후보를 검증하는 동안 배정과 충돌하지 않는 구현은 계속할 수 있다.
- 미커밋 변경을 모두 모을 때까지 기다리지 않고 준비된 의미 있는 단위부터 진행한다.
- 계획의 경계를 바꾼 이유는 작업 기록에 남긴다.
- 이미 같은 변경이 반영돼 차이가 없으면 빈 커밋을 만들지 않는다.
- 로컬 커밋 뒤에도 남은 구현과 전체 목표 검증을 이어 간다.
- 커밋이 요청에서 제외됐으면 변경과 검증 근거를 보존하고 다음 허용된 행동을 진행한다.

## 단계 완료와 전환

| 반환된 결과 | 조율 행동 |
| --- | --- |
| 공간이나 선행 산출물이 준비되지 않았다. | 해당 준비를 맡기거나 독립적인 행동을 선택한다. |
| 구현 범위 안에서 보완할 수 있다. | 필요한 보완을 `wk-build`에 다시 전달한다. |
| 동작·계약·설계 선택이 필요하다. | 영향받는 부분을 [논의](discuss.md)나 [계획](plan.md)으로 돌린다. |
| 의미 있는 변경 단위가 준비됐다. | 후보를 준비한 뒤 변경 단위 검증과 로컬 커밋을 배정한다. |
| 선택한 단위가 다른 미완성 결과에 의존한다. | 필요한 결과를 배정하거나 커밋 경계를 조정한다. |
| 로컬 커밋 뒤에도 필수 결과가 남았다. | 준비된 다음 구현을 배정한다. |
| 필수 구현 결과의 회수·연결·허용된 커밋이 끝났다. | [전체 목표 검증](verify.md#합류-결과-검증)으로 이어 간다. |
| 진행 정책의 종료 조건에 해당한다. | [종료와 재개](../policies/progression.md#종료와-재개)를 적용한다. |

작은 변경의 검사 통과만으로 전체 작업을 완료 처리하지 않는다.
