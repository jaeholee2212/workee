# 작업 조정
1. [장부 규약](../wk-work/references/registry.md)과 각 작업의 담당자를 읽는다.
2. [공통 작업 모델](../wk-work/references/work-model.md)에 따라 작업 관계·계약·선행 산출물을 확인한다.
3. 요청받은 변경 범위 안에서 작성 파일과 공유 자원을 주체별로 배정한다.
4. 같은 파일에 두 작성자를 배정하지 않는다.
5. 담당자 변경 전에는 이전 주체의 중단을 확인한다.
6. 같은 마스터의 하위 작업이 하나의 브랜치·워크트리를 사용하는지 확인한다.

이 스킬은 실행자와 공유 자원의 배치만 조정한다.
에이전트 실행·진행 추적·결과 회수는 `wk-work`가 담당한다.
위임 범위와 필요한 사용자 판단은 [자율 진행과 사용자 판단](../wk-work/policies/progression.md#자율-진행과-사용자-판단)을 따른다.

## 작업 관계
- 포함 관계와 선행 산출물을 구분한다.
- 현재 행동이 소비할 산출물의 실제 준비 여부를 확인한다.
- 존재하지 않는 ID는 연결 전에 바로잡는다.
- 포함 관계의 순환과 실제 산출물 선행 관계의 순환을 각각 확인한다.
- 작업끼리 결과를 주고받으면 소비 시점별로 나눠 확인한다.
- 선행 작업이 done이어도 코드와 자원의 충돌은 따로 확인한다.

## 동시 실행 배정
- 구현을 배정할 때는 각 단위가 생산하거나 소비하는 인터페이스와 동작 계약을 확인한다.
- 공유 계약이 확정됐고 파일·자원 소유권이 분리되면 동시 실행 대상으로 배정한다.
- 다른 단위의 결과가 필요하면 그 결과의 준비 조건과 소비 시점을 배정에 포함한다.
- 같은 계약이나 파일을 함께 바꿔야 하면 하나의 작성 범위로 묶는다.
- 각 실행자의 배정에는 작성 파일·검사 범위·자원 소유권·완료 조건을 포함한다.

## 충돌
- 공유 워크트리의 Git index·커밋·통합 작업은 한 주체에게 맡긴다.
- 다른 작성자가 Git 상태를 변경하는 동안 같은 공간에서 Git 쓰기를 겹치지 않는다.
- 구현 담당자에게 배정한 파일과 Git 쓰기 권한을 구분한다.
- 파일 범위가 달라도 같은 빌드 산출물·프로세스·포트를 쓰는지 확인한다.
- 경로가 달라도 같은 계약과 외부 자원을 쓰는지 확인한다.
- 겹침이 있으면 충돌한 쓰기를 대기로 배정한다.
- 분리할 수 있으면 작성 범위를 다시 나눈다.
- 분리할 수 없으면 이전 주체의 쓰기 종료를 다음 실행의 준비 조건으로 반환한다.

## 후보 검증과 커밋의 자원 배정

- [커밋 후보](../wk-work/references/work-model.md#커밋-후보)를 준비할 때는 후보의 선행 변경과 함께 포함할 결과를 확인한다.
- 후보 준비부터 커밋 생성까지 Git index와 대상 브랜치의 쓰기 담당자를 한 명으로 유지한다.
- 후보 검증에 사용할 위치와 필요한 자원을 배정한다.
- 같은 작업공간에서 검증하면 검사 입력에 영향을 주는 쓰기 종료를 준비 조건에 포함한다.
- 다른 작업의 쓰기를 계속해야 하면 후보만 검증할 격리된 위치를 배정한다.
- 검사와 후보 내용의 일치가 유지되지 않으면 필요한 중단 범위나 격리 조건을 반환한다.

Git 쓰기 직렬화만으로 제품·테스트 파일의 내용이 고정됐다고 판단하지 않는다.
중단·재개·후보 생성·커밋 실행은 배정 결과를 받은 `wk-work`가 조율한다.

## 결과

- 작성 범위·자원 소유자·동시 실행 가능 여부가 정해졌는지 확인한다.
- 남은 충돌에는 영향받는 행동과 해소 조건을 연결한다.
- 동시 실행할 배정과 순서가 필요한 배정을 구분한다.
- 배정·선행 조건·소유권을 [스킬 실행 결과](../wk-work/references/work-model.md#스킬-실행-결과)로 반환한다.
