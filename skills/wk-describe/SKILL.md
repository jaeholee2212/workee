# 현상 기술

1. [장부 규약](../wk-work/references/registry.md)을 읽는다.
2. 지정된 `work.md`를 읽는다.
3. 누가 어떤 상황에서 무엇을 보았는지 적는다.
4. 직접 관찰과 전달받은 보고를 구분한다.
5. 영향을 받는 사용 상황과 영향을 받지 않는 상황을 확인한다.
6. 원인에 대한 주장은 관찰과 분리한다.
7. 현재 현상과 맥락을 한 단락으로 요약한다.

## 관찰 근거

- 버그는 기대 결과와 실제 결과를 같은 조건에서 비교한다.
- 기능 요청은 요청한 기능으로 달성하려는 사용자 결과를 확인한다.
- 상황마다 보고가 다르면 그 차이와 출처를 남긴다.
- 조건과 대상 버전을 기록한다.
- 실행하지 않은 확인은 미실행으로 쓴다.

## 결과

- 요약을 뒷받침하는 관찰과 아직 확인하지 못한 범위를 연결한다.
- 현상의 범위나 설명을 바꿀 질문을 [현재 이해](../wk-work/references/work-model.md#현재-이해)에 반영한다.

## 관찰근거 파일 예시

```
요청 (예상): GET /hello HTTP/1.1
응답 (목표): 200 OK
body (목표): hello
상태: 아직 구현, 실행하지 않음
```
