# 구현 작업공간 준비

논의·계획·재개 확인만 요청받았으면 생성하지 않는다.
승인된 구현 범위의 로컬 작업공간만 준비한다.
필요한 사용자 판단은 [자율 진행과 사용자 판단](../wk-work/policies/progression.md#자율-진행과-사용자-판단)에 따라 반환한다.

## 소유 작업 확인

1. [필요한 기록 규약](../wk-work/references/registry.md#필요한-규약-선택)과 현재 작업을 읽는다.
2. [구현 작업공간](../wk-work/references/work-model.md#구현-작업공간)의 소유·공유·기록 규칙을 읽는다.
3. 상위 링크를 따라 작업공간을 소유할 최상위 작업을 찾는다.
4. 소유 작업에 기록된 구현 작업공간을 확인한다.

공간이 이미 등록됐으면 아래 재사용 확인으로 진행한다.
생성과 공유 기록 갱신은 소유 작업의 담당자 한 명이 수행한다.
다른 담당자가 준비 중이면 준비 담당자와 기다려야 할 결과를 반환한다.
하위 작업마다 새 브랜치나 워크트리를 만들지 않는다.

## 생성 전 확인

1. 진행 정책에 따른 실행 위임 또는 예외의 근거와 허용 범위를 확인한다.
2. 원본 프로젝트가 속한 Git 저장소와 기본 작업공간을 확인한다.
3. 기준 브랜치·커밋과 향후 통합 대상을 계획에서 확인한다.
4. 기준이 지정되지 않았으면 원본 프로젝트의 현재 HEAD 커밋을 기본 기준으로 기록한다.
5. 원본의 미커밋·미추적 변경과 진행 중인 Git 작업을 확인한다.
6. 새 워크트리에서도 같은 설정 원본과 공유 장부를 사용할 수 있는지 확인한다.
7. 브랜치 이름, 경로와 기존 워크트리 등록의 충돌을 확인한다.

실행 권한이 확인되지 않았으면 공간을 생성하지 않고 필요한 근거를 반환한다.
미커밋 변경의 포함 여부가 미확인이면 필요한 선택과 영향받는 파일을 반환한다.
이번 작업에서 제외하기로 확인한 변경은 원본에 그대로 둔다.
미커밋 변경을 자동으로 stash·commit·복사하거나 버리지 않는다.
Git 저장소나 기준 커밋이 없으면 초기화·최초 커밋을 임의로 수행하지 않는다.

확인에 사용할 명령 예시:

```sh
git -C "$SOURCE" rev-parse --path-format=absolute --git-common-dir
git -C "$SOURCE" rev-parse --verify 'HEAD^{commit}'
git -C "$SOURCE" branch --show-current
git -C "$SOURCE" status --short
git -C "$SOURCE" worktree list --porcelain
```

통합 대상이 미정이면 미정으로 기록한다.
통합 대상의 미정은 작업공간 준비를 막지 않는다.

## 생성

- 기본 브랜치 이름은 `sf/<소유 작업 ID>`다.
- 기본 경로는 Git 기본 작업공간 옆의 `<저장소 이름>.wk-worktrees/<소유 작업 ID>`다.
- 사용자가 다른 이름이나 경로를 지정했으면 그 값을 기록한다.
- 저장소, 기준 전체 커밋, 설정 원본, 브랜치와 절대 경로를 소유 작업에 먼저 기록한다.
- 등록되지 않은 동명 브랜치나 기존 경로가 있으면 덮어쓰거나 자동 채택하지 않는다.
- 브랜치 이름은 `git check-ref-format --branch`로 확인한다.

충돌이 없으면 확인한 값을 사용해 생성한다.
`SOURCE`, `BRANCH`, `WORKTREE`, `BASE_COMMIT`은 앞에서 확인한 실제 값으로 설정한다.

```sh
git -C "$SOURCE" worktree add -b "$BRANCH" "$WORKTREE" "$BASE_COMMIT"
```

생성 뒤 Git 등록·브랜치·HEAD와 실제 경로를 대조한다.
실패했으면 남은 브랜치·경로와 대기 사유를 기록한다.
부분 생성 결과를 자동으로 삭제하거나 강제로 다시 만들지 않는다.

## 재사용 확인

1. 기록된 경로가 실제 등록된 워크트리인지 확인한다.
2. Git 공통 디렉터리가 기록된 저장소와 같은지 확인한다.
3. 현재 브랜치가 기록된 브랜치인지 확인한다.
4. 현재 HEAD가 기록된 기준 커밋을 포함하는지 확인한다.
5. 미커밋 변경과 현재 작성자를 확인한다.
6. 확인된 워크트리를 구현·검사의 실행 위치로 반환한다.

재개할 때 HEAD가 기준 커밋과 같을 필요는 없다.
커밋이 추가되거나 미커밋 변경이 있는 정상 작업공간은 그대로 보존한다.
경로가 없거나 브랜치·저장소·기준이 맞지 않으면 원인과 필요한 해결 조건을 반환한다.
기록에 맞추려고 checkout·reset·clean을 실행하지 않는다.

## 결과

소유 작업의 작업공간 기록과 이력에 생성·확인 결과를 남긴다.
하위 작업에는 소유 작업 링크만 남긴다.
저장소·브랜치·경로·기준과 실행 위치가 일치하면 준비를 마친다.
커밋·병합·푸시·브랜치 삭제·워크트리 제거는 준비에 포함하지 않는다.
준비 여부와 확인 근거는 [스킬 실행 결과](../wk-work/references/work-model.md#스킬-실행-결과)로 반환한다.
