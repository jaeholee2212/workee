# 검증
1. [필요한 기록 규약](../wk-work/references/registry.md#필요한-규약-선택), 원래 근거, 완료 조건을 읽는다.
2. 요청된 검증이 변경 단위인지 전체 목표인지 확인한다.
3. 검증 대상의 종류·위치·버전을 식별한다.
4. 요청된 완료 조건별로 필요한 확인 방법과 근거를 연결한다.
5. 아래 대상별 검증을 수행한다.
6. 통과, 실패, 판단 불가, 미실행을 구분해 기록한다.

변경 단위 검증은 해당 변경의 조건과 영향받는 동작을 확인한다.
전체 목표 검증은 합쳐진 결과가 원래 사용자 목표를 충족하는지 확인한다.
변경 단위마다 관련 없는 전체 검사를 반복하지 않는다.

## 구현 결과

- 등록된 구현 공간이 있으면 소유 마스터의 워크트리를 확인한다.
- 실제 대상 위치의 브랜치·코드 버전과 미커밋 변경을 식별한다.
- 그 위치의 실제 사용 지점에서 목표 행동을 확인한다.

## 커밋 후보 검증

커밋할 변경의 검증을 요청받으면 [커밋 후보](../wk-work/references/work-model.md#커밋-후보)의 부모 커밋 `P`·트리 `T`와 검증 위치를 입력으로 받는다.

1. 검증 위치의 제품·테스트·설정 내용이 후보 `T`와 일치하는지 확인한다.
2. 실행에 필요한 다른 미커밋·미추적 소스가 섞이지 않았는지 확인한다.
3. 검사에 영향을 주는 쓰기가 정지했거나 후보의 격리된 사본을 사용하는지 확인한다.
4. 후보 `P`·`T`에서 해당 변경에 필요한 검사를 실행한다.
5. 검사 전후에 검증 입력의 내용과 실행 조건이 유지됐는지 대조한다.
6. 판정과 근거에 후보 `P`·`T`를 연결한다.

- 후보 밖 변경에 의존한 워킹트리의 통과를 후보 검증으로 인정하지 않는다.
- 필요한 선행 변경이 후보에 없으면 해당 의존성과 영향을 반환한다.
- 후보와 실행한 내용의 일치를 확인할 수 없으면 판단 불가로 기록한다.
- 검사가 만든 출력과 검증 입력의 변경을 구분한다.
- 검증 중 입력이 바뀌면 영향받은 근거를 무효로 기록한다.
- 커밋 생성으로 SHA가 생겼더라도 부모 `P`·트리 `T`와 검사 조건이 같으면 유효한 후보 검증 근거를 재사용한다.
- 후보의 통과 여부와 커밋 생성 여부를 구분한다.

## 연구·계획 결과

- 답과 주장에 연결된 출처·관찰·실험 결과를 직접 대조한다.
- 사실과 추론을 구분한다.
- 출처의 대상 버전과 적용 조건이 현재 판단에 맞는지 확인한다.
- 설계·계약·검사 방법이 원래 사용자 목표와 사용 사례를 다루는지 확인한다.
- 방향이나 설계의 선택은 [결정 준비](../wk-decide/references/readiness.md#결정-준비)의 근거를 대조한다.
- 공동 검토·합의가 완료 조건이면 [실제 대화와 위임 기록](../wk-work/references/work-model.md#공동-검토와-실행-위임)을 대조한다.
- 문서의 완성도나 에이전트의 동의만으로 공동 검토 완료를 판정하지 않는다.
- 아직 실행하지 않은 제품 검증을 계획 문서의 근거로 통과 처리하지 않는다.

## 속성 검사
- 변경에 영향받는 계약의 관계와 중요한 실패 경계를 고른다.
- 기존 도구가 있으면 다양한 입력으로 해당 관계를 검사한다.
- 실패 입력과 재현 정보를 보존한다. 예시 검사를 생성 테스트라고 부르지 않는다.

## 근거와 범위
- 대상 위치·브랜치·버전, 검사 방법, 환경, 실제 결과를 함께 적는다.
- 공간 기록이 없는 기존 작업은 검증 대상을 명시하되 검증만을 위해 워크트리를 생성하지 않는다.
- 검증 대상이 바뀌면 영향받은 이전 검증을 만료로 표시한다.
- 불확실한 결과와 검사하지 않은 범위를 통과로 합치지 않는다.

## 전체 목표 확인
전체 목표 검증을 요청받았으면 아래 확인을 수행한다.

- 구현 결과는 원래 문제가 발생한 조건에서 사용자 목표가 달성되는지 확인한다.
- 구현이 계약을 지켜도 원래 문제가 남으면 문제 정의·계약·설계의 누락을 확인한다.
- 새 근거가 기존 판단을 바꾸면 [현재 이해](../wk-work/references/work-model.md#현재-이해)를 갱신할 내용과 영향받는 계획을 반환한다.
- 마스터 구현 작업이면 하위 결과를 합친 실제 동작을 전체 완료 조건과 대조한다.
- 각 하위 작업의 통과 기록만으로 마스터의 검증을 대체하지 않는다.

## 결과

- 요청된 완료 조건마다 판정과 근거 또는 확인하지 못한 이유가 있으면 검증을 마친다.
- 검증 수행의 완료와 대상의 조건 충족을 구분한다.
- 검증 범위·판정·대상 버전·재현 정보·영향받는 판단을 [스킬 실행 결과](../wk-work/references/work-model.md#스킬-실행-결과)로 반환한다.
