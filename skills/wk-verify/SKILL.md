# 검증
1. [장부 규약](../wk-work/references/registry.md), 원래 근거, 완료 조건을 읽는다.
2. 등록된 구현 공간이 있으면 소유 마스터의 워크트리를 확인한다.
3. 실제 대상 위치의 브랜치·코드 버전과 미커밋 변경을 식별한다.
4. 그 위치의 실제 사용 지점에서 목표 행동을 확인한다.
5. 통과, 실패, 판단 불가를 구분해 기록한다.

## 속성 검사
- 계약에서 유지할 관계 하나를 선택한다.
- 기존 도구가 있으면 다양한 입력으로 그 관계를 검사한다.
- 실패 입력과 재현 정보를 보존한다. 예시 검사를 생성 테스트라고 부르지 않는다.

## 근거와 범위
- 대상 위치·브랜치·버전, 검사 방법, 환경, 실제 결과를 함께 적는다.
- 공간 기록이 없는 기존 작업은 검증 대상을 명시하되 검증만을 위해 워크트리를 생성하지 않는다.
- 코드가 바뀌면 영향받은 이전 검증을 만료로 표시한다.
- 불확실한 결과와 검사하지 않은 범위를 통과로 합치지 않는다.

## 전체 목표 확인
- 마스터 작업이면 하위 결과를 합친 실제 동작을 전체 완료 조건과 대조한다.
- 각 하위 작업의 통과 기록만으로 마스터의 검증을 대체하지 않는다.
- 완료 판정은 [공통 작업 모델](../wk-work/references/work-model.md)을 따른다.
