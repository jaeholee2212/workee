# 중단과 인계
1. [장부 규약](../wk-work/references/registry.md)을 읽고 새 변경을 시작하지 않는다.
2. 현재 코드와 문서가 어디에 보존됐는지 확인한다.
3. 구현 공간이 있으면 소유 마스터, 브랜치·워크트리, HEAD와 미커밋 변경을 적는다.
4. 작업 ID, 상위 작업, 현재 단계와 관련 하위 작업을 적는다.
5. 결정, 선행 산출물의 준비 여부, 검증 상태와 미해결을 적는다.
6. [현재 이해](../wk-work/references/work-model.md#현재-이해)의 근거·남은 질문을 확인한다.
7. 중단 사유, 재개 조건과 다음 행동을 적는다.
8. [단계와 상태](../wk-work/references/work-model.md#단계와-상태)에 따라 현재 상태를 기록한다.
9. 담당자의 쓰기가 끝났음을 알린다.

사용자 판단을 기다릴 때도 독립적인 조사를 계속할 수 있으면 그 작업은 active로 둔다.

중단만으로 공유 브랜치나 워크트리를 제거하지 않는다.

## 재개
- [wk-work](../wk-work/SKILL.md)의 시작·재개 절차로 이어간다.
- 인계와 연결된 실제 파일을 먼저 읽는다.
- 이전 기준 이후의 관련 변경을 확인한다.
- 완료한 일을 불필요하게 반복하지 않는다.
- 다음 행동과 상태는 현재 근거로 다시 선택한다.
- 기존 승인 범위 안에서 다음 행동을 실행한다.
