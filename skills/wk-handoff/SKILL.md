# 중단과 인계
1. [장부 규약](../wk-work/references/registry.md)을 읽고 새 변경을 시작하지 않는다.
2. 현재 코드와 문서가 어디에 보존됐는지 확인한다.
3. 구현 공간이 있으면 소유 마스터, 브랜치·워크트리, HEAD와 미커밋 변경을 적는다.
4. 작업 ID, 상위 작업, 현재 단계와 관련 하위 작업을 적는다.
5. 결정, 선행 산출물의 준비 여부, 검증 상태와 미해결을 적는다.
6. [현재 이해](../wk-work/references/work-model.md#현재-이해)의 근거·남은 질문을 확인한다.
7. 전달받은 중단 사유·재개 조건·단계·상태를 기록과 대조한다.
8. 다음 행동에 필요한 입력과 남은 판단을 적는다.
9. 담당자의 쓰기가 끝났음을 알린다.

현재 상태와 실제 작업이 다르면 차이와 근거를 반환한다.

중단만으로 공유 브랜치나 워크트리를 제거하지 않는다.

커밋 후보나 생성한 로컬 커밋이 있으면 다음 내용도 보존한다.

- [커밋 후보](../wk-work/references/work-model.md#커밋-후보)의 부모 `P`·트리 `T`와 검증 위치
- 후보에 연결된 검증 근거와 유효 여부
- 생성한 커밋 SHA와 실제 부모·트리의 일치 확인 결과
- 아직 커밋하지 않은 범위와 기존 스테이징의 담당자

## 재개 자료 확인
- 인계와 연결된 실제 파일을 먼저 읽는다.
- 이전 기준 이후의 관련 변경을 확인한다.
- 재사용할 결과와 다시 확인할 근거를 구분한다.

## 결과

- 다른 실행자가 결과 위치·현재 근거·남은 입력을 복원할 수 있는지 확인한다.
- 인계 자료와 쓰기 종료 여부를 [스킬 실행 결과](../wk-work/references/work-model.md#스킬-실행-결과)로 반환한다.
