# 작은 구현
1. [장부 규약](../wk-work/references/registry.md), 계약, 첫 변경 계획을 읽는다.
2. 전달받은 실행 위치를 소유 마스터에 기록된 브랜치·워크트리와 대조한다.
3. 배정된 작성 파일·허용 동작과 현재 작성자를 확인한다.
4. 현재 변경에 필요한 선행 산출물의 준비 여부를 확인한다.
5. 해당 워크트리에서 목표 동작을 검사 하나로 확인한다.
6. 예상한 실패인지 확인한 뒤 구현으로 진행한다.

작업공간이나 선행 산출물이 준비되지 않았으면 제품·테스트를 변경하지 않는다.
부족한 준비 조건과 영향받는 변경을 반환한다.

## 구현
- 소유 마스터의 워크트리 안에서 첫 검사를 통과시키는 최소 변경을 한다.
- 제품·테스트 변경은 배정된 작성 파일 안에서 수행한다.
- 다른 작성자의 변경은 보존한다.
- 범위 밖 파일 수정이 필요하면 필요한 변경과 영향을 반환한다.
- 관련 없는 정리와 미래 기능은 추가하지 않는다.
- 같은 검사를 다시 실행하고 실제 결과를 남긴다.
- 계약 안에서 해결할 수 있는 실패는 원인을 확인하고 변경·검사를 반복한다.
- 계약 변경이나 새 동작 결정이 필요하면 근거와 영향받는 범위를 반환한다.
- 변경 단위의 검사 통과와 작업 전체의 완료 판정을 구분한다.
- 구현 중의 검사는 해당 실행 위치와 미커밋 상태를 근거로 남긴다.
- 해당 검사만으로 [커밋 후보](../wk-work/references/work-model.md#커밋-후보)의 검증이 끝났다고 판단하지 않는다.
- Git 쓰기는 별도로 배정된 담당자에게 맡긴다.

## 결과

- 허용된 변경과 해당 검사가 완료됐는지 확인한다.
- 실제 변경 파일과 검사 대상 버전·방법·결과를 기록한다.
- 남은 실패와 수행하지 못한 검사를 구분한다.
- 변경이 의존하는 다른 결과와 함께 커밋해야 할 근거를 반환한다.
- 배정된 파일의 쓰기 종료 여부와 진행 중인 검사·점유 자원을 알린다.
- 이 근거를 [스킬 실행 결과](../wk-work/references/work-model.md#스킬-실행-결과)로 반환한다.
