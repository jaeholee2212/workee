# 변경 계획

1. [장부 규약](../wk-work/references/registry.md)과 문제·선택한 방향을 읽는다.
2. 현재 작업과 상위 목표의 완료 조건·기존 계약을 확인한다.
3. 요청된 결과가 설계 구체화인지 실행 계획인지 확인한다.
4. 해당 결과에 필요한 아래 작업을 수행한다.

설계 구체화는 구현 방식과 사용 흐름을 만든다.
실행 계획은 선택된 설계와 계약을 결과 단위·의존성·검사 방법으로 나눈다.
입력이 부족하면 그 입력에 의존하는 부분을 미정으로 남긴다.
전달받은 [공동 검토](../wk-work/references/work-model.md#공동-검토와-실행-위임)의 합의·이견·수정 요청을 입력에 포함한다.

## 설계 구체화

- 사용자 목표를 달성하는 주요 사용 사례를 확인한다.
- 책임, 데이터, 상태, 판단과 외부 효과의 경계를 표시한다.
- 기존 구조를 유지하는 접근을 비교의 기준점으로 둔다.
- 기존 구조가 문제의 원인인지 확인한다.
- 구현 방식이 갈리면 후보별 구조와 판단에 필요한 차이를 적는다.
- 유력한 설계마다 같은 사용 사례와 중요한 실패 상황을 처음부터 끝까지 따라간다.
- 새 추상화가 필요하면 분리할 책임과 추가 비용을 설명한다.
- 설계 내부의 가정은 자료나 작은 실험으로 확인한다.
- 실험 전에 결과에 따라 달라질 설계 내용을 적는다.
- 새 근거에 맞춰 경계와 흐름을 갱신한다.
- 관찰 가능한 동작과 아직 합의되지 않은 동작을 구분한다.
- 주요 선택의 이점·비용과 다른 대안이 더 나은 조건을 구체적인 사용 흐름으로 설명한다.
- 사용자의 피드백으로 설계가 달라졌으면 변경 내용과 이유를 연결한다.
- 문제나 방향에 영향을 주는 근거는 영향받는 판단과 함께 반환한다.

맡은 설계 질문에 답할 수 있는 조사는 이어 간다.
다른 대안의 선택이나 동작 합의가 필요하면 후보·근거·필요한 판단을 반환한다.
실험의 허용 범위는 [자율 진행과 사용자 판단](../wk-work/policies/progression.md#자율-진행과-사용자-판단)을 따른다.

## 실행 계획

- 선택된 설계와 유효한 계약을 입력으로 사용한다.
- 미정인 설계나 계약에 의존하는 작업은 실행 가능한 작업과 구분한다.
- 작은 변경으로 목표 전체를 검증할 수 있으면 단일 작업으로 계획한다.
- 독립적인 결과나 별도 담당 범위가 필요하면 현재 목표를 마스터로 두고 하위 작업을 나눈다.
- 각 하위 작업의 결과가 마스터의 어떤 완료 조건에 기여하는지 적는다.
- 하위 작업마다 범위, 완료 조건, 검사 방법을 정한다.
- 같은 목표의 기존 작업이 있으면 중복 생성 대신 연결 가능성을 확인한다.
- 하위 작업 후보와 상위 목표에 기여하는 결과를 반환한다.
- 선행 산출물마다 제공 작업, 준비 조건과 소비 시점을 적는다.
- 하위 결과의 합류 방법과 마스터 전체의 검증 방법을 적는다.

## 변경·커밋 단위

- 실행 계획에는 한 가지 변경 이유로 설명할 수 있는 잠정 커밋 단위를 제안한다.
- 각 단위에는 결과에 필요한 구현·테스트·제품 문서를 함께 포함한다.
- 이전 커밋 위에서 일관되게 동작하는지 확인할 검사를 연결한다.
- 다른 단위에 의존하면 필요한 선행 결과와 커밋 순서를 적는다.
- 파일 수나 실행자 수를 기준으로 커밋을 나누지 않는다.
- 하나의 커밋 단위가 여러 실행자의 결과를 포함할 수 있음을 구분한다.
- 실제 의존성이 달라지면 경계를 합치거나 나눌 근거를 반환한다.

커밋 경계는 실행 중에 조정할 수 있는 계획이다.
단위별 검사와 합류 후 전체 목표 검증은 각각 계획한다.

## 첫 변경과 검증

- 사용자 행동을 확인하는 가장 작은 변경을 고른다.
- 변경 범위, 검사 방법, 필요한 선행 결과를 적는다.
- 구현 공간을 소유할 최상위 작업과 기준·통합 대상 후보를 적는다.
- 하위 검사가 통과해도 원래 문제가 남는 경우를 전체 검증에 포함한다.

## 완료 근거와 결과

- 설계 구체화는 주요 사용 사례·실패 상황의 흐름과 경계가 근거로 설명되면 완료다.
- 설계 후보의 선택이나 동작 합의가 남으면 실행 계획의 선행 입력으로 명시한다.
- 실행 계획은 각 결과가 완료 조건·선행 산출물·검사 방법에 연결되고 합류 방법이 확인되면 완료다.
- 실행을 막는 미정이 남으면 조건부 계획과 준비된 부분을 구분한다.
- 공동 검토할 설계·계획 초안은 실무 결과로 완료할 수 있다.
- 초안의 완료와 계획 합의·실행 위임을 구분한다.
- 사용자와 검토할 선택점과 그 판단을 돕는 근거를 함께 반환한다.
- 독립적으로 보존할 결과는 [산출물 저장 규칙](../wk-work/references/registry.md#산출물-저장)에 따라 `plan` 용도로 남긴다.
- 설계·계획과 근거·남은 미정을 [스킬 실행 결과](../wk-work/references/work-model.md#스킬-실행-결과)로 반환한다.
