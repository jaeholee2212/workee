# 동작 계약
1. [필요한 기록 규약](../wk-work/references/registry.md#필요한-규약-선택), 완료 조건, 선택한 방향을 읽는다.
2. 관련 사용 사례별 입력 조건과 관찰 가능한 결과를 적는다.
3. 입력과 결과 사이에서 유지할 관계를 적는다.
4. 각 약속을 사용자 목표와 검증 방법에 연결한다.
5. 내부 구현 방식은 계약과 분리한다.

## 경계
- 중요한 실패 상황과 계약을 깨뜨릴 수 있는 경계를 고른다.
- 각 상황의 실패 결과와 그대로 유지할 것을 적는다.
- 결정되지 않은 동작이 있으면 그 동작에 의존하는 구현 범위를 표시한다.
- 자료로 확인할 수 있는 동작은 기존 계약·코드·관찰과 대조한다.
- 중요한 동작의 결정이나 추가 실험이 필요하면 확인할 질문과 영향을 반환한다.
- 필요한 사용자 판단은 [자율 진행과 사용자 판단](../wk-work/policies/progression.md#자율-진행과-사용자-판단)을 따른다.

## 호환성
- 기존 소비자가 요구받던 조건과 받던 결과를 확인한다.
- 새로 요구하는 것과 더 이상 제공하지 않는 것을 표시한다.
- 같은 이름으로 다른 약속을 숨기지 않는다.

## 완료와 결과

- 사용 사례와 실패 상황이 계약으로 설명되는지 확인한다.
- 각 약속의 결과와 유지할 관계를 검증 방법으로 판정할 수 있으면 계약을 완료한다.
- 중요한 동작이 미정이면 해당 계약을 초안으로 구분한다.
- [스킬 실행 결과](../wk-work/references/work-model.md#스킬-실행-결과)에 따라 계약·남은 미정·영향받는 범위를 반환한다.
