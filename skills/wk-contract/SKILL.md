# 동작 계약
1. [장부 규약](../wk-work/references/registry.md), 완료 조건, 선택한 방향을 읽는다.
2. 관련 사용 사례별 입력 조건과 관찰 가능한 결과를 적는다.
3. 입력과 결과 사이에서 유지할 관계를 적는다.
4. 각 약속을 사용자 목표와 검증 방법에 연결한다.
5. 내부 구현 방식은 계약과 분리한다.

## 경계
- 중요한 실패 상황과 계약을 깨뜨릴 수 있는 경계를 고른다.
- 각 상황의 실패 결과와 그대로 유지할 것을 적는다.
- 결정되지 않은 동작이 있으면 그 동작에 의존하는 구현을 대기로 표시한다.
- 확인할 사실은 [탐색 반복](../wk-work/references/exploration.md#탐색-반복)으로 조사한다.
- 필요한 사용자 판단은 [자율 진행과 사용자 판단](../wk-work/SKILL.md#자율-진행과-사용자-판단)을 따른다.

## 호환성
- 기존 소비자가 요구받던 조건과 받던 결과를 확인한다.
- 새로 요구하는 것과 더 이상 제공하지 않는 것을 표시한다.
- 같은 이름으로 다른 약속을 숨기지 않는다.

## 결과

- 사용 사례와 실패 상황이 계약으로 설명되는지 확인한다.
- 남은 미정과 영향받는 실행 범위를 [현재 이해](../wk-work/references/work-model.md#현재-이해)에 반영한다.
