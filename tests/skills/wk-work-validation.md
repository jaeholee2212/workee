# 공동 탐구 변경 검증 결과

검증일: 2026-10-23

대상은 기준 커밋 `8884ce5ffdc37daeb68e9748eb10537798fad817` 이후 이 작업에서 수정한 Workee 스킬이다.
입력과 판정 기준은 [대화 검증 상황](wk-work-conversations.md)에 보존했다.

## 방법과 범위

- 설계 대화와 기대 답변을 상속하지 않은 평가자 3명에게 수정된 스킬과 가상 상황을 전달했다.
- 평가자별 담당은 C1·C2, C3·C4·C5, C6·C7·C8이었다.
- 각 평가자는 필요한 스킬 참조를 읽고 다음 사용자 응답과 내부 다음 행동·상태를 작성했다.
- C1은 같은 평가자에게 사용자 답변을 추가해 다음 턴까지 실행했다.
- C3은 임시 소스를 실제로 읽었다. C7은 임시 README를 실제로 수정했다.
- C7은 재현 문서와 정확히 같은 입력으로 초기화해 한 번 더 실행했다. 최초 보고의 기존 토큰은 `RETRY_ATTEMPS`였고, 재실행에서는 `RETRY_ATTEMPTS`였다.
- 평가자는 소스 저장소를 변경하지 않았다. 제품 구현·작업 등록·워크트리·커밋은 시뮬레이션 범위에서 제외했다.
- 아래 판정은 주 에이전트가 실제 응답·보고·임시 파일 결과를 기준과 대조한 결과다.

### 응답 근거 발췌

C1:
> 모든 timeout에 최대 3회 자동 재시도하자는 권고는 수정해야겠습니다. 제가 timeout을 ‘전달되지 않은 실패’로 취급해서 중복 수신과 취소 후 발송을 놓쳤습니다.

C1 후속:
> 중복 방지를 우선하고, 전달 여부를 끝내 모르는 알림은 재전송하지 않는 조건부 실행 계획으로 정리했습니다.

C2:
> 내부 초안에는 ‘모든 팀원에게 결과 공유’와 ‘검색 로그 90일 보관’이 들어 있지만, 아직 함께 검토하지 않은 제안입니다. 지금 동의하신 범위에 포함하지 않겠습니다.

C3:
> 제공자 코드를 확인했습니다. `supports_idempotency_key = False`로 중복 방지 키를 지원하지 않으며, timeout이 발생해도 메시지가 이미 전달됐을 수 있다고 명시돼 있습니다.

C4:
> 조회 API 유무는 아직 미확인이므로 그 결과에 의존하는 구현은 준비 완료로 표시하지 않겠습니다.

C5:
> 합의한 내용으로 실행 계획을 정리했습니다. 작은 변경이므로 하나의 작업으로 진행할 수 있습니다.

C6:
> 기존의 원본 삭제 금지, 미리보기에서 선택한 파일만 이동, 이름 충돌 시 덮어쓰기 없이 건너뛰기는 유지하겠습니다.

C8:
> 색인 갱신 방식은 검색할 범위와 ‘수정한 문서가 얼마나 빨리 검색돼야 하는지’가 정해진 뒤 비교하겠습니다.

C7 재실행의 실제 변경:

```diff
-Set RETRY_ATTEMPTS to control the maximum number of retries.
+Set MAX_RETRIES to control the maximum number of retries.
```

수정 후 README 전체 바이트가 저장한 원본에서 해당 토큰만 치환한 결과와 같았다.
`config.py`는 `MAX_RETRIES = 3` 그대로였고 저장한 원본도 변경되지 않았다.

## 정적 확인

- `git diff --check`: 통과.
- 수정한 Markdown의 로컬 링크·절 앵커: 대상 존재 확인.
- 수정된 스킬 5개의 frontmatter: 기준 커밋과 동일. 이름·설명·호출 정책을 유지했다.
- `skill-creator/scripts/quick_validate.py` 원본 실행: 기존 `disable-model-invocation` 키를 지원하지 않아 실패했다. 변경 전 HEAD에도 같은 실패가 발생했다.
- 해당 키만 제외한 임시 복사본으로 기본 검증기를 실행해 5개 스킬 모두 통과했다. 호출 정책은 원본과의 동등성 및 기존 boolean 값으로 별도 확인했다. 저장소 파일이나 검증기 자체는 바꾸지 않았다.

## 해석의 한계

8개 상황과 C1의 후속 턴에서 목표한 분기 행동을 관찰했다.
모델·샘플링별 반복 평가나 실제 제품의 전체 개발 흐름 검증은 수행하지 않았다.
대부분의 상황은 주어진 대화 이력에서 다음 한 턴을 실행한 검증이며, 장기 대화의 일관성까지 입증하지 않는다.
Go CLI는 이번 변경 대상이 아니므로 해당 테스트를 공동 탐구의 행동 근거로 사용하지 않았다.
검증 대상은 저장소의 수정본이며 전역 설치본 갱신은 포함하지 않았다.
